The systematic debugging playbook

— · Lesson 5 of 7 · Illustrative sweep + Exact checklist labs

A bad deep-learning score is usually a bug, not a modelling limitation. Follow an ordered decision tree so you change one thing at a time and know what each observation means.

Objectives

  • Predict the loss at initialisation for a \(C\)-class classifier and interpret a mismatch.
  • Run and read a learning-rate range test.
  • Use overfit-one-batch, shape/dtype traces and gradient norms to localise a failure.
  • Apply a saved decision checklist without changing several things at once.

You know this from ML → here it becomes

In classical ML a poor score meant "try different features or regularisation". In deep learning the first questions are mechanical: does the loss start at \(\ln C\)? Can the model memorise eight examples? Are the gradients finite? Only after those pass does model choice become the right conversation.

Intuition: bisect the pipeline

A training run is a chain: data → batch → forward → loss → backward → optimizer → metrics. Every check should cut that chain in half. Overfitting one batch tests everything up to the optimizer. A loss at \(\ln C\) tests the head and labels. A gradient norm tests the backward path. A learning-rate sweep tests the optimizer's scale. You fix the earliest failing link, rerun, and only then move on.

Changing five settings at once destroys this logic: the run improves, and you cannot say which change did it. Keep a baseline checkpoint and revert to it between experiments.

Order matters: baseline → loss at init → overfit one batch → LR range → regularisation. A hyperparameter search before these checks is a search for the bug's favourite hiding place.

The math

1 · Loss at initialisation

With a roughly balanced \(C\)-class dataset and a final linear layer whose logits start near zero, softmax gives \(p_c\approx1/C\). The mean cross-entropy at init is therefore

\[ \mathcal{L}_0 \approx -\ln\frac{1}{C} = \ln C \]

\(C\) is the number of classes and \(\ln\) is the natural logarithm, matching the nats used by PyTorch's cross-entropy.

Worked example. Ten classes: \(\ln 10=2.3026\). Two classes: \(\ln2=0.6931\). Four classes: \(\ln4=1.3863\). A binary classifier reporting \(0.693\) at step 0 is behaving correctly; a 10-class model reporting \(0.69\) at step 0 has a label or head bug — it behaves like a binary model.

2 · LR range test reading

Increase \(\eta\) geometrically from a very small value while training for a few hundred steps, recording the loss. Three regions appear: flat (too small to move), falling (useful), and rising or NaN (too large). A practical pick is the learning rate one decade before the loss minimum, or the steepest-descent point.

Worked example from the stored sweep in the lab. At \(\eta=10^{-5}\) the loss is \(2.30\) (unchanged from \(\ln10\)); at \(10^{-3}\) it is \(1.62\); at \(10^{-2}\) it is \(0.81\); at \(10^{-1}\) it is \(1.14\); at \(10^{0}\) it diverges. The minimum is at \(10^{-2}\). One decade before it is \(10^{-3}\), a conservative choice; the steepest drop in this stored curve sits between \(10^{-3}\) and \(10^{-2}\). Both are readings of the same curve, not universal constants.

3 · Gradient norm check

\[ \lVert g\rVert_2 = \sqrt{\sum_i g_i^2}, \qquad g \leftarrow g\cdot\min\!\left(1,\frac{c}{\lVert g\rVert_2}\right) \]

\(g_i\) are the components of the flattened gradient vector and \(c\) is the clipping threshold. A norm near zero means no learning signal; a norm that grows by \(10\times\) per step means divergence.

Worked example. For \(g=(-0.2,\,0.4)\): \(\lVert g\rVert=\sqrt{0.04+0.16}=\sqrt{0.20}=0.4472\). With \(c=1\), the factor is \(\min(1,1/0.4472)=1\), so nothing changes. For \(g=(3,4)\), \(\lVert g\rVert=5\) and the factor is \(1/5=0.2\), giving \(g=(0.6,0.8)\), whose norm is exactly \(1\).

Lab: range test and decision ladder

The first lab stores a schematic LR-versus-loss sweep; the curve and marker are illustrative, but the marker position is computed from the stored points. The second lab is exact: your answers are saved locally, and the progress meter and next action are computed from them.

Code: a debug script you can paste into a notebook

import math, torch
from torch import nn

device = "cuda" if torch.cuda.is_available() else "cpu"
print("loss at init for C classes:", [round(math.log(c), 4) for c in (2, 4, 10)])

# 1. Shapes and dtypes at the first batch
x, y = next(iter(train_loader))
x, y = x.to(device), y.to(device)
print("batch", tuple(x.shape), x.dtype, "labels", tuple(y.shape), y.dtype,
      "label range", int(y.min()), int(y.max()))

model = make_model().to(device)
logits = model(x[:8])              # (8, C)
print("logits", tuple(logits.shape), logits.dtype)
loss = nn.functional.cross_entropy(logits, y[:8])
print("loss at init", float(loss), "expected about", math.log(logits.shape[1]))

# 2. Overfit ONE batch: loss must approach zero
opt = torch.optim.SGD(model.parameters(), lr=0.05)
for step in range(150):
    opt.zero_grad()
    l = nn.functional.cross_entropy(model(x[:8]), y[:8])
    l.backward()
    opt.step()
    if step in (0, 49, 149):
        print("overfit step", step, "loss", round(float(l), 5))

# 3. Gradient norms after a real batch
opt.zero_grad()
nn.functional.cross_entropy(model(x), y).backward()
norms = [float(p.grad.norm()) for p in model.parameters() if p.grad is not None]
print("grad norm min/max", round(min(norms), 6), round(max(norms), 6),
      "all finite", all(map(math.isfinite, norms)))
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)

# 4. Learning-rate range test: geometric sweep, fresh model each time
for e in range(-6, 1):
    lr = 10.0 ** e
    m = make_model().to(device)
    o = torch.optim.SGD(m.parameters(), lr=lr)
    o.zero_grad()
    loss = nn.functional.cross_entropy(m(x), y)
    loss.backward(); o.step()
    print(f"eta={lr:.1e}  loss_after_one_step={float(loss):.4f}")

The overfit test should drive the loss close to zero on eight examples. If it cannot, the failure is in the model, labels, loss or optimizer — not in dataset size or regularisation. The range test above uses one step per rate for speed; a proper sweep uses a few hundred.

Common mistakes

Changing five things at once

If you alter the LR, architecture, augmentation and loss together, an improvement teaches you nothing. Keep a baseline and bisect the pipeline one check at a time.

Trusting train loss alone

Falling training loss with flat validation accuracy can be memorisation or a label leak. Always check the held-out metric and the data pipeline.

Skipping the baseline

Without a known-good run you cannot tell whether the current result is bad. Record a tiny overfit result and a simple majority-class baseline first.

Misreading \(\ln2\)

A binary cross-entropy near \(0.693\) at step 0 is the correct random-guess loss, not a bug. Compare against \(\ln C\) with the actual class count.

Debug this

A colleague reports "my loss is 0.69 and stuck — the model is broken". It is a balanced binary classifier with a linear output head trained with BCEWithLogitsLoss.

Show the likely cause and the fix

\(0.693=\ln2\) is the expected loss at initialisation for a balanced two-class problem: the logits start near zero, so the probability is near 0.5. Check whether the loss actually moves after a few hundred steps and whether accuracy exceeds the majority-class baseline. If it stays at exactly 0.693 forever, then look for a real bug: zero learning rate, all-zero gradients, detached logits, or labels that never reach the loss.

For a 10-class problem, 0.693 would be suspiciously low at init — probably a label range of \(\{0,1\}\) fed to a 10-way cross-entropy. Print y.min(), y.max() and the logit shape.

Check yourself

Summary

1 · Start with \(\ln C\): \(0.693\) is correct for two classes and \(2.303\) for ten.
2 · Overfit one batch, trace shapes/dtypes, and inspect gradient norms; \(g=(3,4)\) clips to \((0.6,0.8)\) at \(c=1\).
3 · Read the LR sweep from flat to falling to divergent; pick conservatively one decade before the minimum and change one thing at a time.

Cheat sheet — M6·05

  • \(\mathcal L_0\approx\ln C\): 0.693 (2 classes), 1.386 (4), 2.303 (10).
  • LR range: flat → falling → divergent; try one decade below the minimum.
  • \(\lVert g\rVert_2=\sqrt{\sum g_i^2}\); clip by \(\min(1,c/\lVert g\rVert)\).
  • Order: baseline → init loss → one-batch overfit → LR → regularisation.
  • Print shapes, dtypes, label range, grad norms; change one variable per run.
