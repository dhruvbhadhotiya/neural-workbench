Quantization and ONNX export

— · Lesson 4 of 7 · Exact math labs

A model in a notebook is not yet a product. Turn weights into small integers, measure the error exactly, and check that an exported graph computes the same thing.

Objectives

  • Apply the affine quantisation map \(q=\operatorname{round}(x/s)+z\) with real numbers.
  • State the error bound and explain when clipping breaks it.
  • Compute the memory saving from fp32 to INT8 for a known parameter count.
  • Describe PTQ versus QAT and the parity checks an ONNX export needs.

You know this from ML → here it becomes

Rounding a feature to two decimals in a spreadsheet was harmless. Rounding a million trained weights to 8-bit integers changes the function the network computes. The question is no longer "is it smaller?" but "how much error, where, and is the exported graph identical?"

Intuition: a ruler for weights

Quantisation is a change of ruler. Floating point puts precision where the value is; an integer format uses fixed steps of size \(s\) across a chosen range. The step \(s\) is the scale, and \(z\) is the zero point: the integer that represents exactly zero. With \(z=0\) the format is symmetric (good for signed weights); with \(z\neq0\) it is affine (good for non-negative activations such as ReLU outputs).

Post-training quantisation (PTQ) calibrates \(s\) and \(z\) on a small representative sample after training. Quantisation-aware training (QAT) inserts fake-quantisation modules during training so the weights adapt to the coarse grid. PTQ is minutes of work; QAT costs a full training run but usually loses less accuracy.

Quantisation is lossy arithmetic, not compression of information for free. The scale decides the resolution; clipping decides which large values are sacrificed.

The math

1 · Quantise and dequantise

\[ q = \operatorname{clip}\!\left(\operatorname{round}\!\left(\frac{x}{s}\right)+z,\; q_{\min},\,q_{\max}\right), \qquad \hat x = s\,(q-z) \]

\(x\) is the original float value, \(s>0\) the scale (one quantisation step in real units), \(z\) the integer zero point, \(q\) the stored integer and \(\hat x\) the dequantised value. For \(b\)-bit signed weights \(q_{\min}=-2^{b-1}\), \(q_{\max}=2^{b-1}-1\); for unsigned activations \(q_{\min}=0\), \(q_{\max}=2^b-1\). The notation \(\operatorname{clip}\) means "clamp to the representable integer range".

Worked example. Take \(x=1.37\), \(s=0.02\), \(z=-128\), \(b=8\) with \(q_{\min}=-128\), \(q_{\max}=127\). Then \(x/s=1.37/0.02=68.5\), \(\operatorname{round}(68.5)=69\), and \(q=69-128=-59\), which is in range. Dequantising: \(\hat x=0.02\,(-59-(-128))=0.02\cdot69=1.38\). The error is \(x-\hat x=1.37-1.38=-0.01\), magnitude \(0.01\).

2 · Error bound and calibration

\[ |x-\hat x| \le \frac{s}{2} \quad\text{when no clipping occurs.} \]

Rounding to the nearest integer changes \(x/s\) by at most \(1/2\), so multiplying back by \(s\) gives the bound. Once clipping happens the error can be much larger: a value outside \([s(q_{\min}-z),\;s(q_{\max}-z)]\) is simply replaced by the endpoint.

Worked example. With \(s=0.02\), the bound is \(0.01\) — exactly the error measured above. But \(x=-0.42\) with the same \(s,z\) gives \(x/s=-21\), \(q=-21-128=-149\), which is below \(-128\), so it clips to \(-128\) and dequantises to \(0.02\cdot0=0\): error \(0.42\), forty-two times the bound. Choosing \(s\) from the observed range avoids this.

Calibration example. For unsigned 8-bit activations with observed range \([-1,1]\): \(s=(1-(-1))/(255-0)=2/255=0.00784\) and \(z=\operatorname{round}(0-(-1)/s)=\operatorname{round}(127.5)=128\). Dequantising \(q=255\) gives \(0.00784(255-128)=0.996\), an endpoint error of \(0.004\).

3 · Size reduction

\[ R = \frac{\text{bytes}_{\text{fp32}}}{\text{bytes}_{\text{int}}} = \frac{4}{b/8} = \frac{32}{b}, \qquad \text{saving} = 1-\frac{b}{32} \]

\(b\) is the bit width and \(R\) the compression factor relative to fp32 storage.

Worked example. A layer with \(1{,}048{,}576\) weights uses \(1{,}048{,}576\cdot4=4{,}194{,}304\) bytes (4 MiB) in fp32. At INT8 it uses \(1{,}048{,}576\) bytes (1 MiB): \(R=32/8=4\), a saving of \(1-8/32=0.75\), i.e. 75%. At 4 bits it uses 524,288 bytes (0.5 MiB), \(R=8\), saving 87.5%. Scales and zero points add a tiny overhead (one per tensor or per channel).

Code: PTQ, ONNX export and parity

import torch
from torch import nn
import numpy as np

# ---- Post-training static INT8 quantisation --------------------------------
model = nn.Sequential(nn.Conv2d(3, 16, 3, padding=1), nn.ReLU(),
                      nn.Conv2d(16, 16, 3, padding=1), nn.ReLU(),
                      nn.AdaptiveAvgPool2d(1), nn.Flatten(), nn.Linear(16, 10))
model.eval()                                   # folds BN into conv, fixes behaviour

model.qconfig = torch.ao.quantization.get_default_qconfig("x86")
prepared = torch.ao.quantization.prepare(model)
with torch.no_grad():
    for x, _ in calib_loader:                   # ~100–500 representative samples
        prepared(x)                             # collect activation ranges
quantized = torch.ao.quantization.convert(prepared)
with torch.inference_mode():
    y_int8 = quantized(torch.randn(1, 3, 32, 32))   # (1, 10) logits

# ---- ONNX export with a fixed, explicit batch dimension -------------------
dummy = torch.randn(1, 3, 32, 32)
torch.onnx.export(model, dummy, "model.onnx",
                  input_names=["images"], output_names=["logits"],
                  dynamic_axes={"images": {0: "batch"}, "logits": {0: "batch"}},
                  opset_version=13)

# ---- Parity check (requires onnxruntime in the deployment environment) -----
import onnxruntime as ort
sess = ort.InferenceSession("model.onnx", providers=["CPUExecutionProvider"])
x = torch.randn(4, 3, 32, 32)
with torch.no_grad():
    y_torch = model(x).numpy()
y_onnx = sess.run(["logits"], {"images": x.numpy()})[0]
print("shapes", y_torch.shape, y_onnx.shape)
print("max abs parity error", float(np.max(np.abs(y_torch - y_onnx))))

The parity number printed above is measured on your machine; it is not a fixed benchmark. Compare it against the tolerance your application can tolerate, and repeat with several batch sizes if the graph declares a dynamic axis.

Common mistakes

Calibrating on too few samples

A narrow calibration set produces a scale that clips real activations. Use representative data, including the unusual but valid inputs you expect in production.

Exporting in train mode

Dropout stays active and batch norm uses batch statistics, so ONNX and PyTorch disagree. Call model.eval() before tracing and before the parity check.

Dynamic axes left implicit

A graph traced at batch 1 may reject batch 8. Declare which axes are dynamic and test each batch size you plan to serve.

Ignoring the opset

Different opsets implement some operators differently. Pin the opset version and verify parity after any runtime or exporter upgrade.

Debug this

The ONNX model's output differs from PyTorch by about 0.4 on the same input. The export script calls torch.onnx.export(model, dummy, ...) and the model contains dropout and batch norm. The exporter did not print an error.

Show the likely cause and the fix

The model was left in training mode. Dropout randomly zeroes activations during the trace, and batch norm records batch statistics instead of using its running estimates; both differences survive export. Call model.eval() before export and run the PyTorch side of the parity check under torch.no_grad() in eval mode as well.

If the gap remains, compare opset versions and check whether the runtime fused operators. A constant small difference (around 1e-6 for fp32) is normal; 0.4 is a mode or data-order bug.

Summary

1 · Affine quantisation: \(q=\operatorname{clip}(\operatorname{round}(x/s)+z)\), \(\hat x=s(q-z)\); for \(x=1.37,s=0.02,z=-128\), \(q=-59,\hat x=1.38\).
2 · Rounding error is at most \(s/2=0.01\) without clipping; clipping can make it far larger, so calibrate the range.
3 · INT8 stores 1 byte per weight (4× smaller than fp32); export in eval mode and verify parity at each batch size.

Cheat sheet — M6·04

  • \(q=\operatorname{clip}(\operatorname{round}(x/s)+z)\), \(\hat x=s(q-z)\).
  • \(|x-\hat x|\le s/2\) unless clipping; signed \(q\in[-2^{b-1},2^{b-1}-1]\).
  • Calibration: \(s=(x_{\max}-x_{\min})/(q_{\max}-q_{\min})\), \(z=\operatorname{round}(q_{\min}-x_{\min}/s)\).
  • Compression \(R=32/b\): INT8 4×, INT4 8× versus fp32.
  • PTQ calibrates after training; QAT simulates quantisation during training. Export with eval().
