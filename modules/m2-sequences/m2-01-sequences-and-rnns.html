Sequences and recurrent networks

— · Lesson 1 of 7 · Exact math labs

A sentence is not a bag of rows: token 7 depends on tokens 1–6. The recurrent network is the simplest machine that carries that dependence forward — one small matrix, reused at every step.

Objectives

  • Write the RNN recurrence and evaluate it by hand for two timesteps.
  • Unroll the recurrence into a chain and explain what is shared across steps.
  • Count the parameters: \(D H + H^2 + H\).
  • Distinguish many-to-one from many-to-many, and explain why flattening a sequence fails.

You know this from ML → here it becomes

A table model treats every row as independent: the same feature vector gets the same prediction regardless of its neighbours. A sentence violates that assumption — “not good” and “good” share a word but not a meaning. The RNN adds a state \(\mathbf{h}_t\) that summarizes everything read so far, and passes it to the next token.

Intuition: one memory, passed forward

Imagine reading a sentence one word at a time while keeping a single notebook. For each new word you update the notebook using two things: the word itself and the previous note. The notebook after token \(t\) is the hidden state \(\mathbf{h}_t\in\mathbb{R}^{H_{hidden}}\). Crucially, the same update rule — the same weights — is applied at every position. That is parameter sharing over time: a 10-token sentence and a 100-token sentence use the same \(D H + H^2 + H\) numbers.

Unrolling means drawing the same cell \(T\) times with different inputs. The chain has \(T\) boxes but only one set of weights; backpropagation later travels back along that chain (lesson 02). The state at the end is a learned summary of the whole prefix, which is why a classifier can read the last state and emit one label.

Recurrence = apply one fixed function again and again. Depth comes from the sequence length \(T\), not from stacking layers, and it costs no extra parameters.

The math

0 · Symbols

Symbols used in this lesson

  • \(T\): sequence length; \(D = D_{in}\): input width; \(H = H_{hidden}\): hidden width.
  • \(\mathbf{x}_t\in\mathbb{R}^{D}\): input vector at position \(t\); \(\mathbf{h}_t\in\mathbb{R}^{H}\): hidden state after reading it; \(\mathbf{h}_0 = \mathbf{0}\) unless initialized otherwise.
  • \(\mathbf{W}_{xh}\in\mathbb{R}^{D\times H}\): input→hidden matrix; \(\mathbf{W}_{hh}\in\mathbb{R}^{H\times H}\): hidden→hidden matrix; \(\mathbf{b}_h\in\mathbb{R}^{H}\): hidden bias.
  • \(\phi\): nonlinearity (here \(\tanh\)); \(\theta\): all trainable parameters; \(\mathcal{L}\): scalar loss.

1 · The recurrence

\[ \mathbf{h}_t = \phi\!\left(\mathbf{x}_t \mathbf{W}_{xh} + \mathbf{h}_{t-1}\mathbf{W}_{hh} + \mathbf{b}_h\right), \qquad \phi = \tanh \]

Row-vector convention: \(\mathbf{x}_t\) is \(1\times D\), so \(\mathbf{x}_t\mathbf{W}_{xh}\) is \(1\times H\), \(\mathbf{h}_{t-1}\mathbf{W}_{hh}\) is \(1\times H\), and the sum has shape \((1,H)\) before the elementwise tanh. (NOTATION.md §7 uses this same shape convention.)

Worked example. Take \(D=2\), \(H=2\), \(\mathbf{h}_0=(0,0)\), and

\[ \mathbf{W}_{xh}=\begin{bmatrix}0.5&-0.2\\0.3&0.4\end{bmatrix},\quad \mathbf{W}_{hh}=\begin{bmatrix}0.6&0.1\\-0.1&0.5\end{bmatrix},\quad \mathbf{b}_h=(0.1,-0.1) \]

With \(\mathbf{x}_1=(1,0)\):

\[ \mathbf{x}_1\mathbf{W}_{xh}=(0.5,-0.2),\qquad \mathbf{h}_0\mathbf{W}_{hh}=(0,0) \] \[ \mathbf{z}_1=(0.5+0+0.1,\;-0.2+0-0.1)=(0.6,-0.3) \] \[ \mathbf{h}_1=(\tanh 0.6,\;\tanh(-0.3))=(0.5370,\;-0.2913) \]

With \(\mathbf{x}_2=(0,1)\) and the just-computed \(\mathbf{h}_1\):

\[ \mathbf{x}_2\mathbf{W}_{xh}=(0.3,0.4),\qquad \mathbf{h}_1\mathbf{W}_{hh}=(0.5370\cdot0.6+(-0.2913)(-0.1),\;0.5370\cdot0.1+(-0.2913)(0.5))=(0.3513,-0.0919) \] \[ \mathbf{z}_2=(0.3+0.3513+0.1,\;0.4-0.0919-0.1)=(0.7513,0.2081) \] \[ \mathbf{h}_2=(\tanh 0.7513,\;\tanh 0.2081)=(0.6355,\;0.2051) \]

The first coordinate of \(\mathbf{h}_2\) carries information from both \(\mathbf{x}_1\) (through \(\mathbf{h}_1\)) and \(\mathbf{x}_2\). That is the whole point of the state.

2 · Unrolling the graph

\[ \mathbf{h}_3 = \phi\!\left(\mathbf{x}_3\mathbf{W}_{xh} + \phi\!\left(\mathbf{x}_2\mathbf{W}_{xh} + \phi\!\left(\mathbf{x}_1\mathbf{W}_{xh}+\mathbf{h}_0\mathbf{W}_{hh}+\mathbf{b}_h\right)\mathbf{W}_{hh}+\mathbf{b}_h\right)\mathbf{W}_{hh}+\mathbf{b}_h\right) \]

Written out, the recurrence looks nested — but an implementation is a three-line loop, and every box in the chain uses the identical \(\mathbf{W}_{xh},\mathbf{W}_{hh},\mathbf{b}_h\). The lab below steps through exactly the matrices used above.

3 · Parameter count

\[ |\theta| = \underbrace{D H}_{\mathbf{W}_{xh}} + \underbrace{H^2}_{\mathbf{W}_{hh}} + \underbrace{H}_{\mathbf{b}_h} = D H + H^2 + H \]

Worked: for \(D=2,H=2\), \(2\cdot2+2^2+2=4+4+2=10\). For \(D=3,H=4\), \(3\cdot4+4^2+4=12+16+4=32\). The count does not depend on \(T\): a 5-token and a 500-token sequence use the same 32 numbers. This is why RNNs generalize across lengths (within reason) and why flattening is so wasteful.

4 · Reading patterns

Common ways to use the same recurrence

many-to-oneone vector from the last \(\mathbf{h}_T\)sentence sentiment

many-to-many (encoder–decoder)decode after reading the whole inputmachine translation

Why not flatten the \(T\) tokens into one \(TD\)-vector? A linear layer would need \(TD\cdot H\) weights that change when \(T\) changes, it would assign a different weight to every position, and it would discard which token came first. The recurrence keeps one weight per role and lets position live in the state.

Code

PyTorch's nn.RNN implements the recurrence above. With batch_first=True the input is \((N,T,D)\); without it, PyTorch expects \((T,N,D)\). The manual loop below uses the same numbers and prints matching states. 

import torch
from torch import nn

torch.manual_seed(0)

D, H, T, N = 2, 2, 3, 1
x = torch.tensor([[[1., 0.], [0., 1.], [1., 1.]]])   # (N, T, D) = (1, 3, 2)
rnn = nn.RNN(input_size=D, hidden_size=H, batch_first=True, nonlinearity="tanh")

out, h_n = rnn(x)        # out: (1, 3, 2);  h_n: (1, 1, 2)
print(out.shape, h_n.shape)
print("last hidden:", h_n[0, 0].tolist())
print("out[-1] == h_n:", torch.allclose(out[:, -1], h_n[:, 0]))

# Same recurrence by hand, with PyTorch's actual trained-in weights.
W_xh = rnn.weight_ih_l0.T       # (D, H)
W_hh = rnn.weight_hh_l0.T       # (H, H)
b_h  = rnn.bias_ih_l0 + rnn.bias_hh_l0
h = torch.zeros(N, H)
for t in range(T):
    h = torch.tanh(x[:, t] @ W_xh + h @ W_hh + b_h)
    print(t, h[0].tolist())
print("manual == library:", torch.allclose(h, h_n[0]))

print("parameters:", sum(p.numel() for p in rnn.parameters()))  # 10

Common mistakes

batch_first confusion

PyTorch defaults to \((T,N,D)\). If your input is \((N,T,D)\) and you forgot batch_first=True, the layer still runs — it just interprets batch as time. Print shapes before training.

State leaks between sequences

h carries across batches if you reuse it without re-initializing or detaching. Start each independent sequence from zeros; detach when truncating so backprop stops at the chunk boundary.

Padding read as content

Appending pad tokens makes the state wander. Use pack_padded_sequence or a mask so padded positions do not update the state, especially for right-padded batches.

Flattening the sequence

A flattened \(TD\)-vector makes the parameter count grow with \(T\) and destroys weight sharing. If the order matters, use a recurrence (or attention) instead.

Debug this

A reader reports: “my hidden state gets huge over training batches and the loss explodes, even though individual sequences are short.” The training loop is the code above with one line changed.

Show the likely cause and the fix

The hidden state was created once outside the batch loop and passed back in on the next iteration: h = torch.zeros(N, H) sits above the loop instead of inside it. Move initialization inside each sequence (or call h.detach() after each chunk when using truncated BPTT). The state then starts from zero for every example instead of accumulating across unrelated sentences.

Second most likely: shapes are \((N,T,D)\) while the model is in default batch_first=False mode. Print x.shape and h.shape first.

Summary

1 · The RNN applies one shared cell at every position: h_t = tanh(x_t W_xh + h_{t−1} W_hh + b_h).
2 · Unrolling gives a T-step chain with only DH + H² + H parameters, independent of T.
3 · The final state summarizes the prefix (many-to-one); pads must be masked or packed so they do not corrupt it.

Cheat sheet — M2·01

  • \(\mathbf{h}_t=\tanh(\mathbf{x}_t\mathbf{W}_{xh}+\mathbf{h}_{t-1}\mathbf{W}_{hh}+\mathbf{b}_h)\), \(\mathbf{h}_0=0\).
  • Shapes: \(\mathbf{x}_t\in\mathbb{R}^{D}\), \(\mathbf{W}_{xh}\in\mathbb{R}^{D\times H}\), \(\mathbf{W}_{hh}\in\mathbb{R}^{H\times H}\).
  • Parameters: \(DH+H^2+H\); independent of sequence length \(T\).
  • Worked: \(D=2,H=2\), \(\mathbf{x}_1=(1,0)\) → \(\mathbf{z}_1=(0.6,-0.3)\) → \(\mathbf{h}_1=(0.537,-0.291)\).
  • PyTorch: input \((N,T,D)\) needs batch_first=True; default is \((T,N,D)\).
  • Many-to-one: final \(h_T\) → label. Many-to-many: \(g(h_t)\) per token.
