Tokenization: subwords you can count

— · Lesson 4 of 7 · Exact math labs

Before a neural network can read a word, it must split text into IDs. BPE is a simple, countable compression algorithm — you can run its merges on a scrap of paper and get the same vocabulary the code gets.

Objectives

  • Run BPE merges by hand on low lower lowest and count the vocabulary.
  • Compute pair frequency and compression ratio with concrete numbers.
  • Explain WordPiece's ## marker, SentencePiece's whitespace handling and OOV fallback.
  • Choose a vocabulary size and avoid train/test tokenizer leakage.

You know this from ML → here it becomes

Classical NLP used a fixed feature vocabulary: one column per word, everything else mapped to “unknown”. Subword tokenizers learn that vocabulary from the training corpus, compressing common strings into single tokens while still being able to spell rare ones.

Intuition: merge the most common pair

Start with characters plus an end-of-word marker. Count every adjacent pair, merge the most frequent one into a new symbol, and repeat. Common prefixes like lo become one token after a few steps; rare words remain a short chain of pieces. Nothing probabilistic is happening — the algorithm is a deterministic loop over counts.

The vocabulary budget is a knob. A small vocabulary keeps the embedding matrix cheap but produces long token sequences and more <unk>; a large one gives short sequences and a bigger lookup table. Byte-level BPE guarantees zero unknown tokens by falling back to the 256 byte symbols.

A tokenizer is a learned compression scheme. BPE spends its vocabulary budget on the pairs that save the most tokens; everything else is spelled out.

The math

0 · Symbols

Symbols used in this lesson

  • \(V\): vocabulary size (number of distinct symbols, including special tokens).
  • \(c(a,b)\): frequency of the adjacent pair \((a,b)\) in the corpus, counted over symbol sequences.
  • \(N_0\): number of symbols before merging; \(N_k\): after \(k\) merges.
  • \(r = N_0/N_k\): compression ratio; \(\text{EOW}=\text{</w>}\) marks a word boundary.

1 · The BPE merge rule

\[ (a^\star,b^\star)=\arg\max_{(a,b)} c(a,b),\qquad \text{new symbol}=a^\star b^\star \]

Ties are broken deterministically (this course uses the lexicographically smaller concatenation). Each merge replaces every occurrence of that adjacent pair in every word and adds one symbol to the vocabulary.

Worked example — low lower lowest, four merges. Start:

\(N_0=4+6+7=17\). Initial vocabulary: {l,o,w,e,r,s,t,EOW}, so \(V_0=8\).

Step 1 breaks a 3–3 tie between (l,o) and (o,w) because “lo” sorts first; step 4 breaks a five-way 1–1 tie because “low</w>” sorts before “lower”, “lowes”, “st” and “t</w>”. After step 1 the sequences are lo w EOW, lo w e r EOW, lo w e s t EOW; after step 4 they are low</w>, lowe r EOW, lowe s t EOW. The compression ratio is \(r = N_0/N_4 = 17/8 = 2.125\). Encoding a new word lowest with these four merges gives lowe s t EOW — four tokens.

2 · WordPiece and SentencePiece

WordPiece also merges pairs, but chooses by the training likelihood gain rather than raw frequency, and marks non-initial pieces with ##. For example playing might become play ##ing; the marker tells the decoder that ##ing attaches to the previous piece.

SentencePiece trains directly on raw text (whitespace is just another character, usually escaped as ▁) so it does not need language-specific pre-tokenization. Byte-level BPE starts from 256 bytes, so every Unicode string has a valid encoding and <unk> is unnecessary.

3 · Vocabulary size and special tokens

With \(V\) symbols and embedding width \(D\), the embedding table has \(V\cdot D\) parameters. Worked: \(V=30{,}000\), \(D=512\) gives \(30{,}000\cdot512=15{,}360{,}000\) parameters — before any decoder projection. Budget special tokens explicitly: if you need <pad>, <bos>, <eos> and <unk>, only \(V-4\) slots remain for learned subwords.

Code

The whole trainer fits in a short pure-Python function; no external package is needed.

from collections import Counter

def bpe(corpus, n_merges=4):
    words = [list(w) + ["</w>"] for w in corpus.split()]
    vocab = sorted({s for w in words for s in w})
    merges = []
    for _ in range(n_merges):
        counts = Counter()
        for w in words:
            counts.update(zip(w, w[1:]))
        if not counts:
            break
        # highest count; ties broken by the smaller concatenated string
        pair = min(counts, key=lambda p: (-counts[p], p[0] + p[1]))
        merges.append(pair)
        new = "".join(pair)
        if new not in vocab:
            vocab.append(new)
        merged = []
        for w in words:
            out, i = [], 0
            while i < len(w):
                if i + 1 < len(w) and tuple(w[i:i+2]) == pair:
                    out.append(new); i += 2
                else:
                    out.append(w[i]); i += 1
            merged.append(out)
        words = merged
    return words, vocab, merges

words, vocab, merges = bpe("low lower lowest", 4)
print("merges:", merges)      # [('l','o'), ('lo','w'), ('low','e'), ('low','</w>')]
print("vocab size:", len(vocab))   # 12
print("tokens:", sum(len(w) for w in words))  # 8 (= 17 − 3 − 3 − 2 − 1)

def encode(word, merges):
    seq = list(word) + ["</w>"]
    for a, b in merges:
        out, i = [], 0
        while i < len(seq):
            if i + 1 < len(seq) and seq[i] == a and seq[i+1] == b:
                out.append(a + b); i += 2
            else:
                out.append(seq[i]); i += 1
        seq = out
    return seq

print(encode("lowest", merges))    # ['lowe', 's', 't', '</w>']

# The resulting IDs would feed an embedding lookup:
# ids = [token_to_id[t] for t in encode("lowest", merges)]
# pip install tokenizers   (inside this course: example only, no download at runtime)
from tokenizers import Tokenizer, models, pre_tokenizers, trainers

tok = Tokenizer(models.BPE(unk_token="<unk>"))
tok.pre_tokenizer = pre_tokenizers.Whitespace()
trainer = trainers.BpeTrainer(
    vocab_size=1000,
    special_tokens=["<pad>", "<unk>", "<bos>", "<eos>"],
)
tok.train_from_file("train.txt", trainer=trainer)   # TRAIN split only!

ids = tok.encode("low lower lowest").ids
print(len(ids), tok.decode(ids))
print(tok.token_to_id("<pad>"), tok.vocab_size)

# Byte-level BPE has a byte fallback, so every string is encodable:
from tokenizers import decoders
tok.decoder = decoders.BPEDecoder(suffix="</w>")

Common mistakes

Tokenizer leakage

Training BPE on train + test text leaks test vocabulary statistics into the pipeline. Fit the tokenizer on the training split only, then apply it unchanged to validation and test.

Tokens are not words

One word can become several tokens. Sequence lengths, attention masks and label alignment (for tagging) must be computed after tokenization, not before.

Forgetting special tokens

If <pad> and <bos> are not reserved, training can assign them ordinary IDs and the model learns from padding. Reserve them before training.

Vocabulary too small

A tiny \(V\) leaves most words as long rare-piece chains and makes <unk> common. Check the unknown rate on held-out text, not training text.

Debug this

A reader reports: “I set vocab_size=1000 but <unk> dominates my validation set.” The tokenizer was trained normally, with no byte fallback.

Show the likely cause and the fix

The merge budget was exhausted before common validation subwords were learned — or the trainer stopped early because the requested \(V\) included four special tokens but the corpus could only supply a few hundred useful merges. Raise \(V\), train on more in-domain text, or switch to byte-level BPE with a byte fallback so no input can map entirely to <unk>. Also confirm that <unk> is reserved and that you are not feeding the tokenizer raw Unicode bytes through an ASCII-only alphabet.

Measure the unknown-token rate on text the tokenizer never saw; a low training rate can hide a severe held-out failure.

Summary

1 · BPE repeatedly merges the most frequent adjacent pair; on low lower lowest the order is lo → low → lowe → low</w>.
2 · That grows V from 8 to 12 and compresses 17 symbols to 8, a ratio of 2.125.
3 · Fit on train only, reserve special tokens, and use byte fallback if unknown tokens must vanish.

Cheat sheet — M2·04

  • \((a^\star,b^\star)=\arg\max c(a,b)\); new symbol \(a^\star b^\star\); tie-break by smaller concatenation.
  • \(\text{EOW}=</w>\); BPE on low lower lowest: lo, low, lowe, low</w> → \(V=12\).
  • \(r=N_0/N_k\): here \(17/8=2.125\). Embedding parameters \(=V D\); V=30,000, D=512 → 15,360,000.
  • WordPiece uses ## for continuation pieces; SentencePiece models whitespace as a symbol.
  • Byte-level BPE has a 256-byte fallback → no <unk>.
  • Always fit the tokenizer on the training split only; reserve <pad>, <bos>, <eos>, <unk>.
