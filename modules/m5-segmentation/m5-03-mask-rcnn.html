Mask R-CNN: detection with a pixel mask per box

— · Lesson 3 of 4 · Exact math labs

Faster R-CNN proposes boxes; Mask R-CNN adds a small fully convolutional mask head — and refuses to round the box coordinates that tell it where to look.

Objectives

  • Explain the two stages: region proposal network (RPN), then per-RoI box and mask heads.
  • Compute RoIPool and RoIAlign outputs on the same fractional region.
  • Derive RPN anchor targets and the per-pixel mask BCE loss.
  • Run inference with torchvision and read the box and mask tensor shapes.

You know this from ML → here it becomes

An object detector returns a list of boxes \((x_1,y_1,x_2,y_2)\). Mask R-CNN returns those boxes plus a binary mask for each one. Because a mask is spatial, the operation that extracts a fixed-size feature window must preserve sub-pixel alignment: rounding a box to integers shifts the mask by exactly the pixels you cannot afford to lose.

Intuition: two stages, three losses

Stage one, the RPN, slides a small conv over the backbone feature map and predicts, for each of \(k\) anchors per location, an objectness score and four box deltas. Stage two takes the selected proposals, pools a fixed-size feature window from the shared feature map with RoIAlign, and predicts a class, a refined box and a \(28\times28\) mask. Training therefore optimises three losses at once:

\[ \mathcal{L}=\mathcal{L}_{\mathrm{rpn}}+\mathcal{L}_{\mathrm{box}}+\mathcal{L}_{\mathrm{mask}} \]

The mask branch is fully convolutional: it sees a \(14\times14\times256\) RoI feature and produces one probability per class per output cell. Keeping masks class-specific (rather than sharing one binary mask across classes) is what lets the mask head compete on accuracy.

Boxes tolerate a pixel of jitter; masks do not. RoIAlign exists because quantising a proposal turns a half-pixel error into a visible boundary error.

The math

1 · RoIPool vs RoIAlign on a 4×4 grid

RoIPool rounds first: \(x_1'=\lfloor0.8\rfloor=0\), \(y_1'=\lfloor0.8\rfloor=0\), \(x_2'=\lceil3.1\rceil=4\), \(y_2'=\lceil2.6\rceil=3\). The integer region is \(4\times3\); split into \(2\times2\) bins gives columns {0,1} and {2,3}, rows {0,1} and {2}. Taking the max in each bin yields \(\begin{bmatrix}6&8\\10&12\end{bmatrix}\).

RoIAlign never rounds. Bin width \(=(3.1-0.8)/2=1.15\), bin height \(=(2.6-0.8)/2=0.9\), with two samples per bin at offsets \(0.25\) and \(0.75\). For the top-left bin's first sample: \(x=0.8+0.25\cdot1.15=1.0875\), \(y=0.8+0.25\cdot0.9=1.025\). After the standard half-cell shift, \(s_x=x-0.5=0.5875\), \(s_y=y-0.5=0.525\), so the four neighbours are \((0,0),(1,0),(0,1),(1,1)\) with bilinear weights

\[ w_{00}=(1-0.5875)(1-0.525)=0.19594,\quad w_{10}=0.5875(1-0.525)=0.27906 \] \[ w_{01}=(1-0.5875)(0.525)=0.21656,\quad w_{11}=0.5875\cdot0.525=0.30844 \]

The sampled value is \(1w_{00}+2w_{10}+5w_{01}+6w_{11} \approx0.19594+0.55813+1.08281+1.85063=3.6875\). Averaging the four samples in that bin and repeating for the other bins gives the aligned output; the lab computes all four live.

2 · RPN anchor targets

An anchor is a reference box with centre \((x_c,y_c)\), area \(s^2\) and aspect ratio \(r\):

\[ w = s\sqrt{r},\qquad h = s/\sqrt{r} \]

Worked example. At one location with \(s=16\) and \(r\in\{1:1,2:1,1:2\}\): \(r=1\) gives \(w=h=16\); \(r=2\) gives \(w=16\sqrt2\approx22.6,\ h=16/\sqrt2\approx11.3\); \(r=1/2\) swaps them. With three scales \(s\in\{8,16,32\}\) there are \(k=3\cdot3=9\) anchors per location.

Targets come from IoU with the nearest ground-truth box. An anchor at the same centre as a \(16\times16\) ground truth with \(s=16,r=1\) has area \(256\), intersection \(256\), union \(256\) and \(\mathrm{IoU}=1\) — a positive. The \(s=32,r=1\) anchor has area \(1024\), intersection \(256\), union \(1024\) and \(\mathrm{IoU}=0.25\) — a negative. The usual rule is positive if \(\mathrm{IoU}>0.7\) (or the best anchor for a ground truth), negative if \(<0.3\), ignored in between; roughly half of each mini-batch is sampled as positives.

3 · The mask loss is per pixel, per RoI

For a positive RoI, the mask head outputs logits \(\hat z_{c,i,j}\) for each class \(c\) and cell \((i,j)\); the loss is the mean BCE over all \(K\) classes and cells:

\[ \mathcal{L}_{\mathrm{mask}}=\frac{1}{R}\sum_{r=1}^{R}\frac{1}{K}\sum_{c=1}^{K}\sum_{i,j} \mathrm{BCE}\big(\sigma(\hat z^{(r)}_{c,i,j}),\,g^{(r)}_{c,i,j}\big) \]

\(R\) is the number of sampled positive RoIs and \(g\in\{0,1\}\) the resized ground-truth mask cell. Worked check. One class, four cells with probabilities \(p=[0.9,0.8,0.2,0.1]\) and targets \(g=[1,1,0,0]\): the BCE terms are \(-\log0.9=0.105\), \(-\log0.8=0.223\), \(-\log0.8=0.223\), \(-\log0.9=0.105\), so the mean is \((0.105+0.223+0.223+0.105)/4\approx0.164\). Only class-specific targets contribute; the box and classification losses are computed on the same RoIs but with different targets.

Code

A torchvision Mask R-CNN with a two-class mask predictor. Weights are not downloaded: this is a synthetic-image shape/inference check, and the printed box count depends on the randomly initialised model. 

import torch
from torchvision.models.detection import maskrcnn_resnet50_fpn
from torchvision.models.detection.mask_rcnn import MaskRCNNPredictor

NUM_CLASSES = 2                      # background + one thing class

# weights=None: no download, randomly initialised. The API shape is the same.
model = maskrcnn_resnet50_fpn(weights=None, weights_backbone=None, num_classes=91)
in_ch = model.roi_heads.mask_predictor.conv5_mask.in_channels
model.roi_heads.mask_predictor = MaskRCNNPredictor(in_ch, 256, NUM_CLASSES)
model.eval()                          # required: BN and the RPN behave differently in train mode

image = torch.rand(3, 224, 224)       # synthetic (C,H,W) image, values in [0,1]
with torch.no_grad():
    preds = model([image])            # torchvision expects a LIST of images

p = preds[0]
print("boxes", tuple(p["boxes"].shape))   # (N_det, 4), x1 y1 x2 y2 in image pixels
print("labels", tuple(p["labels"].shape)) # (N_det,)
print("scores", tuple(p["scores"].shape)) # (N_det,)
print("masks", tuple(p["masks"].shape))   # (N_det, 1, 28, 28), probabilities

keep = p["scores"] > 0.5                 # threshold at INFERENCE, not during training
small_masks = p["masks"][keep]
print("thresholded masks", tuple(small_masks.shape))  # (N_keep, 1, 28, 28)

# If you resize the image, scale boxes the same way:
scale = 224 / 448
boxes_scaled = p["boxes"] * scale

torchvision returns masks on \([0,1]\) with shape \((N_{det},K_{classes},28,28)\). Threshold them to obtain a binary mask; evaluate with COCO-style IoU averaged over IoU thresholds 0.50:0.95 (state the thresholds whenever you quote mAP).

Common mistakes

Resizing without adjusting boxes

If the image is scaled by \(a\) but boxes are not, predictions land at the wrong coordinates — the classic “masks offset by a few pixels” bug. Keep a single resize/scale helper for images and targets.

NMS in the wrong place

Proposals are selected with NMS at inference; during training all sampled positives and negatives are used. Applying an inference threshold to training targets starves the mask head of examples.

Mask threshold too high

A 0.9 threshold makes masks tiny and destroys IoU. Start near 0.5 and tune on validation IoU; remember the head outputs probabilities, not hard labels.

Forgetting model.eval()

In train mode the RPN samples proposals differently and batch-norm uses batch statistics. Inference on one image in train mode can fail outright or give unstable masks.

Debug this

Boxes look roughly right but every predicted mask sits a few pixels up and to the left of its object. The mask head, RoIAlign and thresholds were all checked.

Show the likely cause and the fix

The image was resized after the boxes (or the boxes were resized with a different scale factor / offset). RoIAlign then samples the correct feature window for the wrong rectangle. Track the exact transform — scale and padding — and apply the identical map to boxes before cropping. With letterboxing, subtract the padding offset as well as dividing by the scale, and invert the transform before drawing predictions on the original image.

Summary

1 · The RPN scores 9 anchors per location; the second head refines boxes, classifies and predicts a per-class mask.
2 · RoIPool rounds a fractional box and loses half a cell; RoIAlign bilinearly samples 2×2 points in each of 2×2 bins — on the worked grid the first sample is 3.6875.
3 · Mask BCE is averaged over positive RoIs, classes and cells; correct alignment and matched resize transforms matter more than thresholds.

Cheat sheet — M5·03

  • Two stages: RPN proposals → RoIAlign → box, class and mask heads.
  • Anchor: \(w=s\sqrt r,\ h=s/\sqrt r\); three scales × three ratios = 9.
  • Positive anchor: IoU > 0.7 or best for a GT; negative: IoU < 0.3.
  • RoIAlign: bin size \(=(x_2-x_1)/n\); 2×2 samples at offsets 0.25/0.75 with bilinear weights.
  • RoIPool quantises with floor/ceil; RoIAlign never rounds coordinates.
  • Torchvision output: boxes \((N_{det},4)\), masks \((N_{det},K,28,28)\); call model.eval().
