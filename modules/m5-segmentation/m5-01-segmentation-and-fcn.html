Segmentation and FCNs: a label for every pixel

— · Lesson 1 of 4 · Exact math labs

Classification answers one question per image. Segmentation answers one question per pixel — and forces you to get spatial resolution back after every pooling layer.

Objectives

  • Distinguish semantic, instance and panoptic segmentation from the colour rules that define them.
  • Compute a transposed-convolution output size, including output_padding.
  • Explain why bilinear upsampling is smooth and transposed convolutions can leave a checkerboard.
  • Calculate effective kernel size K_eff = D(K−1)+1 for ASPP dilation rates.

You know this from ML → here it becomes

A classifier maps one image to one label: \(X\in\mathbb{R}^{N\times C\times H\times W}\) becomes \(\hat y\in\{1,\dots,K_{classes}\}^N\). A segmentation model keeps the grid: its output is \(\hat Y\in\{1,\dots,K_{classes}\}^{N\times H\times W}\). The loss is still cross-entropy — now summed over every pixel — and the target is no longer a scalar but an image you can draw.

Intuition: three ways to label a grid

Semantic segmentation gives every pixel a class id: all cars share one colour. Instance segmentation separates objects of the same class: car 1 and car 2 get different colours, but the road gets none. Panoptic segmentation combines them: stuff classes (road, sky) get a class colour, thing classes (car, person) get one colour per instance. In the lab, you paint class labels and the widget derives instances by connected components — the same 4-neighbour rule an instance head must learn from data.

A classifier ends with global average pooling, which throws the \(H,W\) axes away. The fully convolutional network (FCN) replaces that with a \(1\times1\) convolution that maps channels to class logits while keeping the grid, then upsamples back to input resolution. Skips from early layers add the fine detail that pooling destroyed. The output tensor is \((N,K_{classes},H,W)\) — logits, one channel per class, before a per-pixel softmax.

Pooling buys context and costs resolution. Every design decision in segmentation is a way to recover the lost pixels without losing that context.

The math

1 · Transposed-convolution output size

Let \(H\) be the input side, \(K\) the kernel, \(S\) the stride, \(P\) the padding, \(D\) the dilation rate and \(o\) output_padding. A transposed convolution (sometimes called a deconvolution) produces

\[ H' = (H-1)S - 2P + D(K-1) + o + 1 \]

Worked example. An FCN upsampling block takes \(H=4\) with \(K=3,\ S=2,\ P=1,\ D=1,\ o=1\): \(H' = (4-1)\cdot2 - 2\cdot1 + 1\cdot(3-1) + 1 + 1 = 6 - 2 + 2 + 1 + 1 = 8\). So \(4\times4 \to 8\times8\), exactly \(2\times\). Change only \(o\) to 0 and you get \(6-2+2+0+1=7\): the classic off-by-one that makes skip concatenation fail.

2 · Upsampling 4×4 → 8×8 by factor 2

For factor \(f=2\), nearest neighbour repeats each source pixel \(f\) times: output pixel \(y\) reads input \(\lfloor y/f\rfloor\). Row \(0\) of the source \([0,4,8,12]\) becomes \([0,0,4,4,8,8,12,12]\).

Bilinear reads source coordinate \(s_y=\frac{y+0.5}{f}-0.5\), clamped to \([0,H-1]\), with fractional part \(f_y=s_y-\lfloor s_y\rfloor\). On row \(y=0\): \(s_y=0.25-0.5=-0.25\to0\), so \(f_y=0\) and only the horizontal weights matter. For \(x=1\): \(s_x=0.25\), \(f_x=0.25\), giving \(0\cdot0.75+4\cdot0.25=1\). Continuing, \(x=2\to3\), \(x=3\to5\), \(x=4\to7\), \(x=5\to9\), \(x=6\to11\), \(x=7\to12\): the interpolated row is \([0,1,3,5,7,9,11,12]\). Smooth, but it invents intermediate values.

A transposed convolution with a learnable kernel does not interpolate — it learns a pattern. With stride 2 and kernel \(\begin{bmatrix}1&0.5\\0.5&0.25\end{bmatrix}\), one active input pixel paints the \(2\times2\) block \(\begin{bmatrix}1&0.5\\0.5&0.25\end{bmatrix}\) into the output; neighbouring blocks overlap unevenly, producing the visible checkerboard artefact the lab shows.

3 · Dilated kernels and ASPP

Dilating a \(K\)-tap kernel by rate \(D\) inserts \(D-1\) zeros between taps, so the effective kernel size is

\[ K_{eff} = D(K-1)+1 \]

Worked ASPP example. Atrous spatial pyramid pooling uses \(K=3\) with rates \(r\in\{1,6,12,18\}\). Substituting: \(r=1\to K_{eff}=1\cdot2+1=3\); \(r=6\to 6\cdot2+1=13\); \(r=12\to 12\cdot2+1=25\); \(r=18\to 18\cdot2+1=37\). The \(r=12\) branch sees a \(25\times25\) patch with only \(3^2=9\) weights — the same parameter count as a plain \(3\times3\), but a 25-tap-wide view. On a \(41\times41\) feature map it covers \(25^2/41^2 \approx 0.372\), about 37% of the map.

4 · The loss is per pixel, not per image

With logits \(\hat z_{n,c,i,j}\) at pixel \((i,j)\) and target class \(y_{n,i,j}\), the per-pixel cross-entropy (mean reduction over \(N\cdot H\cdot W\)) is

\[ \mathcal{L} = -\frac{1}{NHW}\sum_{n=1}^{N}\sum_{i=1}^{H}\sum_{j=1}^{W} \log\,\mathrm{softmax}(\hat z_n)_{y_{n,i,j}} \]

Worked check. One pixel with logits \([2,1,0.1]\) and target class 1: softmax \(=[0.659,0.242,0.099]\), so the loss is \(-\log 0.242\approx1.419\). Four pixels with losses \(1.42,0.30,0.70,0.20\) give \((1.42+0.30+0.70+0.20)/4=0.655\). Replacing this with one label per image would discard exactly the \(H\cdot W\) answers you are being graded on.

Code

The FCN head, an explicit transposed-convolution shape print, and an ASPP block. Shapes are written in the course convention \((N,C,H,W)\). 

import torch
from torch import nn
from torch.nn import functional as F

class FCNHead(nn.Module):
    """Turn encoder features into per-pixel class logits."""
    def __init__(self, c_in, classes):
        super().__init__()
        self.score = nn.Conv2d(c_in, classes, kernel_size=1)   # (N,C,H,W) -> (N,K,H,W)

    def forward(self, feat, size):
        logits = self.score(feat)
        # Masks are integers: resize with nearest, never bilinear.
        return F.interpolate(logits, size=size, mode="bilinear", align_corners=False)

# Transposed conv: verify the size arithmetic from the lesson.
up = nn.ConvTranspose2d(8, 4, kernel_size=3, stride=2, padding=1, output_padding=1)
x = torch.zeros(1, 8, 4, 4)                 # (N=1, C=8, H=4, W=4)
print(tuple(up(x).shape))                    # (1, 4, 8, 8)  -> 4*2 = 8
no_op = nn.ConvTranspose2d(8, 4, 3, 2, 1, 0)
print(tuple(no_op(x).shape))                 # (1, 4, 7, 7)  -> off by one

class ASPP(nn.Module):
    """Four parallel fields of view; Keff = D*(K-1)+1."""
    def __init__(self, c_in, classes):
        super().__init__()
        self.branches = nn.ModuleList([
            nn.Conv2d(c_in, 64, 1),
            nn.Conv2d(c_in, 64, 3, padding=6,  dilation=6),   # Keff = 13
            nn.Conv2d(c_in, 64, 3, padding=12, dilation=12),  # Keff = 25
            nn.Conv2d(c_in, 64, 3, padding=18, dilation=18),  # Keff = 37
        ])
        self.global_branch = nn.Sequential(
            nn.AdaptiveAvgPool2d(1), nn.Conv2d(c_in, 64, 1))
        self.out = nn.Conv2d(64 * 5, classes, 1)

    def forward(self, x):
        parts = [b(x) for b in self.branches]
        g = self.global_branch(x)
        parts.append(F.interpolate(g, size=x.shape[-2:], mode="bilinear", align_corners=False))
        return self.out(torch.cat(parts, dim=1))              # (N, classes, H, W)

Note the asymmetry: logits (float) may be resized bilinearly, but integer masks and labels must be resized with mode="nearest" or they become fractional class ids.

Common mistakes

Ignoring output_padding

With \(K=3,S=2,P=1\), a \(16\times16\) map gives 31, not 32, unless output_padding=1. The skip concatenation then fails by one pixel. Compute \(H'\) before wiring the decoder.

Softmax over the wrong dimension

Logits have shape \((N,K_{classes},H,W)\). Class is channel dimension 1. Softmax over dimension 0 mixes batch items and produces nonsense probabilities that still sum to 1.

Bilinear-resizing a mask

A mask holds integer class ids. Bilinear interpolation invents ids such as 1.4; nearest neighbour preserves labels. Resize float logits smoothly, labels never.

Ignoring class imbalance

Background can cover 95% of a mask. Plain cross-entropy is then minimised by predicting background everywhere; use class weights, Dice loss, or both.

Debug this

A reader writes a transposed convolution with \(K=3, S=2, P=1\) on a \(16\times16\) feature map, expecting \(32\times32\) to add to a skip. They get \(31\times31\) and PyTorch reports a concatenation size mismatch. Why?

Show the cause and the fix

\((16-1)\cdot2-2\cdot1+1\cdot(3-1)+0+1 = 30-2+2+1 = 31\). The missing term is output_padding=1: it adds exactly one row and one column, giving \(30-2+2+1+1=32\). Set nn.ConvTranspose2d(c_in, c_out, 3, stride=2, padding=1, output_padding=1). If your decoder uses an interpolate-then-conv block instead, set its output size explicitly to the skip's \(H,W\).

Second thing to check: the skip and the upsampled map must agree in channels too. Padding fixes space; it does not fix a wrong c_out.

Summary

1 · Semantic labels pixels by class, instance labels separate objects, panoptic combines the two rules.
2 · A transposed conv grows space by \((H-1)S-2P+D(K-1)+o+1\); forgetting \(o\) is the off-by-one in most skip mismatches.
3 · Upsampling trades smoothness (bilinear) for learned detail (transposed conv, with possible checkerboard), while dilation widens context for free via \(K_{eff}=D(K-1)+1\).

Cheat sheet — M5·01

  • Output tensor: \((N,K_{classes},H,W)\); softmax over class axis 1.
  • Transposed conv: \(H'=(H-1)S-2P+D(K-1)+o+1\).
  • Nearest index: \(\lfloor y/f\rfloor\); bilinear source: \((y+0.5)/f-0.5\).
  • Dilated kernel: \(K_{eff}=D(K-1)+1\); ASPP \(K=3\), rates 1/6/12/18 → 3/13/25/37.
  • Per-pixel CE: mean of \(-\log p_{y_{i,j}}\) over all \(N\cdot H\cdot W\) pixels.
  • Resize float logits bilinearly; resize integer masks with nearest only.
