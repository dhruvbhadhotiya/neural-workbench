Convolution: sliding filters over pixels

— · Lesson 2 of 8 · Exact math labs

One output pixel is a dot product between a small weight patch and the image. Change the kernel, stride, padding or dilation and you can predict the exact output shape and every output number.

Objectives

  • Compute Conv2d output height and width from H, W, K, S, P and dilation D.
  • Read a 3×3 kernel as a feature detector and evaluate cross-correlation by hand.
  • Explain what padding, stride and dilation change about the computation.
  • Describe channel mixing and the (C_out, C_in, K_H, K_W) weight layout.

You know this from ML → here it becomes

A linear model has one weight per feature. A conv has one weight per relative offset — the same small pattern is dragged across the image. The sum you compute at each stop is familiar: it is a dot product, just like a neuron's weighted sum.

Intuition: a filter is a stubby neuron

A Conv2d layer slides a \(K\times K\) kernel over the input. At each position it multiplies overlapping values and sums them into one output. With zero padding \(P\), the output keeps runnable positions even at the border; with stride \(S\) the kernel jumps \(S\) pixels; with dilation \(D\) the kernel's taps are spaced \(D-1\) pixels apart.

In channels, each output filter owns one \(K\times K\) kernel per input channel. The results are summed and one bias is added. Thus a filter can combine colour channels, not just detect a shape in one of them. PyTorch stores the weight as \((C_{out}, C_{in}, K_H, K_W)\) — output filters first, input channels second.

Symbols used in this lesson

\(H,W\): input height/width · \(K\): kernel size (assume square) · \(S\): stride · \(P\): zero padding per side · \(D\): dilation · \(C_{in},C_{out}\): input/output channels · \(x,y\): input/output values · \(o\): output-channel index.

PyTorch's Conv2d computes cross-correlation, not the mathematical convolution (which flips the kernel). Because kernel weights are learned, the flip makes no difference to expressive power — but it matters when you hand-code a fixed kernel.

The math

1 · The cross-correlation sum

Using the NCHW convention from NOTATION.md, one output value is

\[ y_{i,j,o} = \sum_{c=1}^{C_{in}}\sum_{u=1}^{K}\sum_{v=1}^{K} x_{iS+uD,\; jS+vD,\; c}\, W_{o,c,u,v} + b_o \]

Worked example, \(C_{in}=C_{out}=1\). Take the 5×5 input \(\begin{bmatrix}1&2&3&4&5\\6&7&8&9&1\\2&3&4&5&6\\7&8&9&1&2\\3&4&5&6&7\end{bmatrix}\) and kernel \(\begin{bmatrix}1&0&-1\\0&1&0\\-1&0&1\end{bmatrix}\). The top-left output (before padding effects) is \(1\cdot1 + 2\cdot0 + 3\cdot(-1) + 6\cdot0 + 7\cdot1 + 8\cdot0 + 2\cdot(-1)+3\cdot0+4\cdot1 = 1-3+7-2+4 = \mathbf{7}\). With \(S=2, P=1\) the full computed output is \(\begin{bmatrix}8&5&-4\\3&-5&14\\-5&12&8\end{bmatrix}\) — the lab reproduces these nine numbers.

2 · Output size — the one formula

\[ H' = \left\lfloor \frac{H + 2P - D(K-1) - 1}{S} \right\rfloor + 1, \qquad W' = \left\lfloor \frac{W + 2P - D(K-1) - 1}{S} \right\rfloor + 1 \]

Worked example: \(H=W=5, K=3, S=2, P=1, D=1\): \(\lfloor(5+2-1\cdot2-1)/2\rfloor+1 = \lfloor4/2\rfloor+1 = \mathbf{3}\), so the output is 3×3.

“Same” padding means choosing \(P\) to keep \(H'=H\) when \(S=1\): for odd \(K=3\), \(P=(K-1)/2=1\). For even \(K=2\), no integer \(P\) satisfies \(2P=K-1\); PyTorch's padding="same" puts the extra row/column at the bottom/right.

3 · Dilation and cost

The effective kernel span is \(K_{\mathrm{eff}} = D(K-1)+1\). Worked: \(K=3, D=2\) gives \(2(3-1)+1 = 5\): nine weights look at a 5×5 region without paying for 25 weights.

Multiply-adds for one conv layer (one image): \(\mathrm{MACs}=H'W'C_{in}C_{out}K^2\). Worked: \(3\cdot3\cdot1\cdot1\cdot9 = 81\) MACs, i.e. 162 floating-point operations if each MAC is counted as a multiply and an add. Parameters remain \(C_{out}C_{in}K^2+C_{out}=1\cdot1\cdot9+1=10\) — sharing again.

4 · 1×1 convolutions

With \(K=1\), the spatial sum vanishes and the layer is a per-pixel linear map across channels: \(y_{i,j,o}=\sum_c x_{i,j,c}W_{o,c}+b_o\). Worked: \(C_{in}=32, C_{out}=16\) gives \(16\cdot32+16 = 528\) parameters. This is how bottleneck blocks shrink or expand channel counts without touching \(H,W\).

Hands-on labs

Every number below is computed in your browser from the inputs you can change.

Code

import torch
from torch import nn

x = torch.randn(1, 3, 32, 32)   # (N, C_in, H, W) = (1, 3, 32, 32)

settings = [
    dict(kernel_size=3, stride=1, padding=1, dilation=1),
    dict(kernel_size=3, stride=2, padding=1, dilation=1),
    dict(kernel_size=3, stride=1, padding=2, dilation=2),
]
for s in settings:
    layer = nn.Conv2d(3, 16, **s)     # weight (16, 3, 3, 3)
    y = layer(x)                      # (1, 16, H', W')
    print(s, "->", tuple(y.shape),
          "params", sum(p.numel() for p in layer.parameters()))

# (1, 3, 32, 32) -> (1,16,32,32), (1,16,16,16), (1,16,32,32)
# conv params are 16*3*9 + 16 = 448 in all three cases
import tensorflow as tf

# Keras uses NHWC internally: (N, H, W, C). Commented below as NCHW equivalents.
x = tf.random.normal((1, 32, 32, 3))   # NCHW would be (1, 3, 32, 32)

for k, s, p, dil in [(3, 1, 1, 1), (3, 2, 1, 1), (3, 1, 2, 2)]:
    if p == 2 and dil == 2:             # padding="same" handles even effective pads
        layer = tf.keras.layers.Conv2D(16, k, strides=s, dilation_rate=dil,
                                       padding="same")
    else:
        layer = tf.keras.layers.Conv2D(16, k, strides=s, padding=p and "same" or "valid")
    y = layer(x)                        # (1, H', W', 16); NCHW: (1, 16, H', W')
    print((k, s, p, dil), "->", y.shape, "params", layer.count_params())

# Keras weight layout is (K_H, K_W, C_in, C_out): same 448 numbers as PyTorch.

Common mistakes

“Same” padding with even kernels

For K=2 there is no integer P with 2P=K−1. Frameworks assign the extra pad asymmetrically; check the printed H′ instead of assuming perfect symmetry.

Forgetting dilation's effective size

A 3×3 kernel with D=2 spans 5×5 pixels. Padding chosen for K=3 can leave too little input and silently shrink the output.

Channel order in the weight tensor

PyTorch conv weights are (C_out, C_in, K_H, K_W). Keras uses (K_H, K_W, C_in, C_out). Swapping them gives shape errors or a wrong parameter count.

Conv versus mathematical convolution

PyTorch implements cross-correlation (no kernel flip). A hand-typed Sobel kernel needs no flipping to match the library output.

Debug this

A reader expects a 4×4 output from a 5×5 input with a 3×3 kernel and padding 1, but prints a 2×2 tensor. One hyperparameter is wrong.

Show the likely cause and the fix

Stride was left at 2. Substituting into the formula: \(\lfloor(5+2\cdot1-3-1)/2\rfloor+1 = \lfloor3/2\rfloor+1 = 2\). With \(S=1\): \(\lfloor4/1\rfloor+1 = 5\) — that would be a 5×5 “same” output, so to get 4×4 use padding 0 with stride 1: \(\lfloor(5-3)/1\rfloor+1=4\).

Print layer.stride, layer.padding and layer.dilation together; the error is almost always one of those three.

Check yourself

Summary

1 · Conv2d computes cross-correlation: a dot product between a shared K×K kernel and each input patch, summed over input channels.
2 · Output size is floor((H+2P−D(K−1)−1)/S)+1; for 5×5, K=3, S=2, P=1 it is 3×3.
3 · Parameters depend on C_in, C_out and K (not H,W); MACs also depend on H′W′ and the dilation changes the span K_eff=D(K−1)+1.

Cheat sheet — M1·02

  • \(y_{i,j,o}=\sum_{c,u,v} x_{iS+uD,jS+vD,c}\,W_{o,c,u,v}+b_o\).
  • \(H'=\lfloor (H+2P-D(K-1)-1)/S\rfloor+1\).
  • Worked: \((5+2-2-1)/2=2\Rightarrow H'=3\).
  • Parameters \(C_{out}C_{in}K^2+C_{out}\); MACs \(H'W'C_{in}C_{out}K^2\).
  • Effective kernel \(K_{\mathrm{eff}}=D(K-1)+1\); 3×3 with D=2 spans 5×5.
  • PyTorch weight \((C_{out},C_{in},K_H,K_W)\); Keras \((K_H,K_W,C_{in},C_{out})\).
