Hyperparameter search and augmentation

— · Lesson 6 of 8 · Exact math labs

At ten GPU-hours per trial, how you choose hyperparameters matters as much as which values you choose. Augmentation is the other cheap regulariser: it changes the data, not the model.

Objectives

  • Compare grid, random, Bayesian and Hyperband search using a fixed budget.
  • Explain why random search covers an important low-dimensional subspace well.
  • Compute mixup and cutout transformations with explicit numbers.
  • Build an augmentation pipeline and state the rules for test-time augmentation.

You know this from ML → here it becomes

GridSearchCV over five parameters already costs many fits; with deep models each fit is expensive. The search problem becomes a budget-allocation problem. Augmentation is the deep-learning version of adding invariance to your estimator — except you generate the new examples.

Intuition: search the dimensions that matter

In most hyperparameter problems a couple of settings dominate the result — often learning rate and weight decay — while others barely matter. A grid spends trials evenly on every axis; random search gives every trial a fresh combination and therefore samples the important axis many more times with the same budget. Bayesian methods fit a surrogate model of the objective and spend trials where improvement looks likely. Hyperband trains many configurations briefly and promotes the promising ones.

Augmentation applies the same thought to data: give the model many plausible versions of each image so the invariances become part of the task. Crops, flips and colour jitter encode “position, orientation and lighting should not change the label.” Mixup and CutMix go further by mixing two examples and their labels.

Symbols

\(p\): fraction of the search range that matters · \(n\): number of trials · \(\tilde x\): mixed input · \(\lambda\sim\mathrm{Beta}(\alpha,\alpha)\): mix coefficient · \(y_i,y_j\): labels of two examples · \(\epsilon_{cut}\): cutout area fraction.

The math

1 · Random-search coverage

If a fraction \(p\) of one axis contains useful values, one random trial misses it with probability \(1-p\); \(n\) independent trials miss it with \((1-p)^n\):

\[ P(\text{at least one hit}) = 1-(1-p)^n \]

Worked: \(p=0.1, n=30\) gives \(1-0.9^{30}\approx1-0.0424 = 0.9576\), about a 96% chance. A 30-point grid spread as 6×5 over two axes places only 6 distinct values on the important axis. Search learning rate on a log scale: sampling \(\log_{10}\eta\) uniformly gives even coverage of \(10^{-5}\) to \(10^{-1}\).

2 · Mixup and CutMix

\[ \tilde x = \lambda x_i + (1-\lambda)x_j, \qquad \tilde y = \lambda y_i + (1-\lambda)y_j \]

Worked with \(\lambda=0.3\), \(x_i=(1,2)\), \(x_j=(4,8)\): \(\tilde x=(0.3\cdot1+0.7\cdot4,\;0.3\cdot2+0.7\cdot8)=(3.1,6.2)\). A one-hot label is mixed in exactly the same proportions.

Cutout removes an \(8\times8\) patch from a \(32\times32\) image: \(\epsilon_{cut}=64/1024=0.0625\), i.e. 6.25% of the pixels. CutMix replaces that patch with the corresponding patch from another image and mixes labels by the patch-area ratio.

3 · Test-time augmentation (TTA)

\[ \hat y = \frac{1}{M}\sum_{m=1}^{M} f(a_m(x)) \]

Worked with \(M=2\) and class-probability predictions \(p_1=(0.8,0.2)\), \(p_2=(0.6,0.4)\): the TTA prediction is \((0.7,0.3)\). This is only valid when every \(a_m\) preserves the label — flipping traffic-sign images can change their meaning.

import torch
from torchvision import transforms as T
from torchvision.transforms import v2

train_tf = v2.Compose([
    v2.RandomResizedCrop(32, scale=(0.6, 1.0)),   # input (3,32,32) -> (3,32,32)
    v2.RandomHorizontalFlip(p=0.5),
    v2.ColorJitter(brightness=0.2, contrast=0.2),
    v2.ToTensor(),
    v2.Normalize(mean=(0.5, 0.5, 0.5), std=(0.5, 0.5, 0.5)),
])
val_tf = v2.Compose([v2.ToTensor(),
                     v2.Normalize((0.5,)*3, (0.5,)*3)])  # no random ops

# Mixup / CutMix operate on a batch: x (N,3,32,32), y (N,) class indices
mix = v2.MixUp(alpha=0.2, num_classes=10)
cut = v2.CutMix(alpha=1.0, num_classes=10)
xb, yb = torch.randn(8, 3, 32, 32), torch.randint(0, 10, (8,))
xm, ym = mix(xb, yb)     # ym is (8,10), softly mixed labels
xc, yc = cut(xb, yb)     # a rectangular patch is swapped between images

# Random search on a log scale for LR, linear for weight decay
import numpy as np
rng = np.random.default_rng(0)
trials = [(10 ** rng.uniform(-5, -1), rng.uniform(1e-6, 1e-2)) for _ in range(30)]
print(trials[0])
import keras_tuner as kt
from tensorflow import keras

def build(hp):
    lr = hp.Float("lr", 1e-5, 1e-1, sampling="log")   # log scale!
    wd = hp.Float("wd", 1e-6, 1e-2)
    inputs = keras.Input((32, 32, 3))                 # NHWC in Keras
    x = keras.layers.RandomFlip("horizontal")(inputs)
    x = keras.layers.RandomCrop(32, 4)(x)
    x = keras.layers.Conv2D(hp.Int("filters", 16, 64, step=16), 3,
                            padding="same", activation="relu")(x)
    x = keras.layers.GlobalAveragePooling2D()(x)
    outputs = keras.layers.Dense(10)(x)
    model = keras.Model(inputs, outputs)
    model.compile(optimizer=keras.optimizers.AdamW(lr, weight_decay=wd),
                  loss=keras.losses.SparseCategoricalCrossentropy(from_logits=True))
    return model

tuner = kt.RandomSearch(build, objective="val_loss", max_trials=30,
                        directory="tune", project_name="cifar")

Common mistakes

Searching LR linearly

Learning rate spans orders of magnitude. Sample log10(lr) uniformly; a linear sweep from 0 to 0.1 wastes most trials on unusably large values.

Augmenting before normalisation incorrectly

Colour jitter belongs on raw or unnormalised images; applying brightness changes after subtracting the dataset mean shifts values in the wrong space.

Label-semantics-changing TTA

Vertical flips, 180° rotations or hue shifts can change the target for digits, signs and medical images. Only average predictions over label-preserving views.

No seed control

Search and augmentation both use randomness. Seed the sampler and the pipeline so trials are comparable and results reproducible.

Debug this

A reader adds TTA with horizontal and vertical flips to a classifier for the letter “b” versus “d”, and validation accuracy drops.

Show the likely cause and the fix

A vertical flip maps “b” to something like “p” and a horizontal flip maps it to “d” — the augmentations changed the label. Averaging those predictions mixes evidence for different classes. Keep TTA to transformations that preserve the label (small crops, mild colour changes when colour is irrelevant, horizontal flips only for objects whose left-right orientation is not semantic).

Check by displaying a few augmented images with their labels before trusting a TTA score.

Summary

1 · Random search samples promising axes repeatedly: with p=0.1 and 30 trials the hit probability is 1−0.9^30≈0.96; Bayesian methods model the objective and Hyperband promotes survivors.
2 · Mixup mixes inputs and labels with lambda: (1,2) and (4,8) at lambda=0.3 give (3.1,6.2); an 8×8 cutout on 32×32 removes 6.25% of pixels.
3 · TTA averages predictions over label-preserving views only; seeds and correct normalisation order make search and augmentation reproducible.

Cheat sheet — M1·06

  • Random coverage: \(P(\text{hit})=1-(1-p)^n\); \(p=0.1,n=30\Rightarrow0.9576\).
  • Mixup: \(\tilde x=\lambda x_i+(1-\lambda)x_j\), \(\tilde y=\lambda y_i+(1-\lambda)y_j\).
  • Worked: \(\lambda=0.3\Rightarrow(3.1,6.2)\).
  • Cutout area fraction: \(8\cdot8/(32\cdot32)=0.0625\).
  • Sample \(\log_{10}\eta\) uniformly, not \(\eta\).
  • TTA: \(\hat y=\frac1M\sum_m f(a_m(x))\) for label-preserving \(a_m\).
