Why convolutions: locality, sharing, equivariance

— · Lesson 1 of 8 · Exact math labs

A 224×224 RGB image is 150,528 numbers. A fully connected first layer to 64 units needs 9,633,856 parameters; a 3×3 convolutional layer with 64 filters needs 1,792. This lesson explains where that gap comes from and what it costs.

Objectives

  • Name the three inductive biases of a convolutional layer: locality, weight sharing and equivariance.
  • Compute fully connected versus convolutional first-layer parameter counts with the formulas and check them in a lab.
  • Distinguish translation equivariance from translation invariance.
  • Explain why a convolutional prior reduces the amount of data a vision model needs.

You know this from ML → here it becomes

In a tabular model every column is a feature with its own weight. Flatten pixels and the same logic gives one weight per pixel per hidden unit — but a cat's ear is the same detector wherever it sits. Convolution encodes that belief: one small filter, reused at every location.

Intuition: three biases, one layer

Let the input be a tensor \(\mathsf{X}\in\mathbb{R}^{C\times H\times W}\): \(C\) channels (3 for RGB), height \(H\), width \(W\). A fully connected (FC) layer mixes every one of the \(C H W\) input numbers into every output unit. A convolutional layer makes three assumptions:

  1. Locality. One output at \((i,j)\) looks only at a \(K\times K\) patch around \((i,j)\). Early visual features are local: edges, colour changes, corners.
  2. Weight sharing. The same \(K\times K\) weights are used at every location, so a detector learned in one corner works in every corner.
  3. Equivariance. Shift the input by \(\tau\) and the output feature map shifts by the same \(\tau\): \(f(\tau \mathsf{X})=\tau f(\mathsf{X})\).

Locality is not the same as sparsity of the learned weights after training: it is a structural constraint on which weights exist at all. Sharing is not just fewer parameters for its own sake — it forces the model to reuse evidence from every location. Finally, equivariance is about feature maps; pooling or global averaging can later produce (approximate) invariance, where the output does not move at all.

Convolution is a prior: it says “the useful patterns are small, and the same pattern matters everywhere.” That prior is what lets a vision model learn from fewer examples.

The math

1 · Fully connected first layer

With \(D\) hidden units, each of the \(C H W\) pixels connects to each unit, plus one bias per unit:

\[ n_{\mathrm{FC}} = C H W D + D \]

Worked example: \(C=3, H=W=224, D=64\). \(C H W = 3\cdot 224\cdot 224 = 150{,}528\); \(150{,}528\cdot 64 = 9{,}633{,}792\); \(+64\) biases gives \(\mathbf{9{,}633{,}856}\) parameters. The input alone is already 150,528 numbers per image — this is the “flatten explosion”.

2 · Convolutional first layer

A conv layer has \(C_{out}\) filters, each of shape \(C_{in}\times K\times K\), plus one bias per output filter \(o\):

\[ n_{\mathrm{conv}} = C_{out}\,C_{in}\,K^2 + C_{out} \]

Worked example: \(C_{in}=3, C_{out}=64, K=3\). \(64\cdot 3\cdot 3^2 = 64\cdot 3\cdot 9 = 1{,}728\), plus \(64\) biases gives \(\mathbf{1{,}792}\) parameters. The ratio is \(9{,}633{,}856 / 1{,}792 \approx 5{,}376\times\) fewer numbers for this first layer. Sharing is the reason: the 1,728 weights are reused at all \(224\times224\) positions.

3 · Equivariance statement

Write \(\tau\) for a translation that moves the image by \((\Delta i,\Delta j)\). A layer \(f\) is translation equivariant when

\[ f(\tau \mathsf{X}) = \tau f(\mathsf{X}) \]

Worked check on a 1-D example: kernel \(w=[1,-1]\) on signal \(x=[0,1,2,3]\) gives cross-correlation \([0\cdot1-1\cdot 1,\;1\cdot1-2\cdot1,\;2\cdot1-3\cdot1]=[-1,-1,-1]\). Shift the input right by one: \(x'=[0,0,1,2]\) gives \([0, -1, -1]\). That is the original output shifted right with the new first position padded by zero — the pattern moved, it did not change shape.

Global average pooling computes \(\frac{1}{HW}\sum_{i,j} A_{i,j,o}\) for each channel \(o\), which discards location: it is invariant, not equivariant. Max pooling over \(2\times2\) windows is only approximately invariant to shifts of one pixel.

Hands-on labs

Every number below is computed in your browser from the inputs you can change.

Code

import torch
from torch import nn

# Same input, two ways of connecting it. NCHW everywhere:
x = torch.randn(1, 3, 224, 224)          # (N=1, C=3, H=224, W=224)

fc = nn.Linear(3 * 224 * 224, 64)        # flattens to (1, 150528)
conv = nn.Conv2d(3, 64, kernel_size=3, padding=1)

def count(model):
    return sum(p.numel() for p in model.parameters())

print("FC first layer   ", count(fc))    # 9633856
print("Conv first layer ", count(conv))  # 1792
print("ratio            ", count(fc) / count(conv))  # ~5376.04

y_fc = fc(x.reshape(1, -1))              # (1, 64)
y_conv = conv(x)                         # (1, 64, 224, 224) with padding=1
print(y_fc.shape, y_conv.shape)

Common mistakes

Equivariance ≠ invariance

Equivariant features move with the object; invariant outputs stay fixed. A conv layer is equivariant. Max pooling or GAP later buys (approximate) invariance — at the cost of location.

“Convolutions are just sparse FC layers”

Sparsity alone would still give each location its own weights. Weight sharing is the second constraint, and it is what makes the parameter count independent of H and W.

Ignoring the flatten explosion

The cheap conv stack often ends in a huge Linear layer. ResNet-18's final fc alone has 513,000 parameters (counts from tools/params.py); always count the head too.

Assuming more data is the only fix

If images are scarce, a wrong prior costs more than a small dataset. Convs embed the locality/sharing prior; a fully connected model must learn it from examples.

Debug this

A reader writes nn.Linear(150528, 10) for a laptop CIFAR-10 experiment with a batch of 128. The first matrix alone has \(150{,}528\cdot 10=1{,}505{,}280\) numbers, and activation memory for the batch is about \(128\cdot150{,}528\cdot4\approx 77\) MB — before gradients, optimizer state or any hidden layer.

Show the likely cause and the fix

The input was flattened too early. Keep the spatial structure and use a conv stem, then downsample: CIFAR images are \(32\times32\), so \(3\cdot32\cdot32=3{,}072\) inputs, not 150,528 (that number belongs to \(224\times224\)). A conv stack with pooling reduces both the parameter count and the activation size. If an FC head is required, pool first and flatten the small map.

Also check the input convention: NCHW means channel first. A NHWC-shaped array silently interpreted as NCHW gives nonsense shapes instead of an out-of-memory error.

Check yourself

Summary

1 · Locality restricts each output to a K×K patch; sharing reuses the same weights at every location.
2 · For 3×224×224 → 64 the counts are 9,633,856 (FC) versus 1,792 (3×3 conv) — about 5,376× fewer parameters.
3 · Convs are translation equivariant, f(τx)=τf(x); pooling and GAP trade location for (approximate) invariance.

Cheat sheet — M1·01

  • FC params: \(n_{\mathrm{FC}} = C H W D + D\).
  • Conv params: \(n_{\mathrm{conv}} = C_{out} C_{in} K^2 + C_{out}\).
  • Worked: \(3\cdot224\cdot224\cdot64+64=9{,}633{,}856\); \(64\cdot3\cdot9+64=1{,}792\).
  • Equivariance: \(f(\tau x)=\tau f(x)\); invariance: \(f(\tau x)=f(x)\).
  • NCHW convention: conv weight \((C_{out},C_{in},K_H,K_W)\), activation \((N,C,H,W)\).
  • 1×1 conv: \(C_{in}C_{out}+C_{out}\) parameters; mixes channels only.
