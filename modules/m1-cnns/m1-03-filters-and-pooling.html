Feature maps, filters and pooling

— · Lesson 3 of 8 · Exact math labs

A filter is the detector; a feature map is where and how strongly it fired. Pooling shrinks maps and trades precise location for robustness to small shifts.

Objectives

  • Distinguish a filter (the weights) from a feature map (the conv output).
  • Compute max-pool and average-pool outputs by hand and in the lab.
  • Explain the shape change of global average pooling, (N,C,H,W) → (N,C).
  • Explain why pooling gives approximate translation invariance and what it costs.

You know this from ML → here it becomes

In classical CV you designed edge filters by hand and then downsampled to save compute. Here the filters are learned by gradient descent; pooling is the same downsampling step, made part of the model graph.

Intuition: where a detector fired

Apply 32 filters to an image and you get 32 feature maps, each of shape \(H'\times W'\). Channel \(o\) of the output answers one question: “does filter \(o\) find its pattern here?” A positive, large value means a strong response; zero or negative means little or no match. Early filters look for edges and colour blobs; later filters combine those into textures and parts — but every one is still just a dot product followed by a nonlinearity.

Pooling then summarizes small neighbourhoods. Max pooling asks “was the pattern present anywhere in this 2×2 window?” — which is why it keeps a strong response even after a one-pixel shift. Average pooling asks “how much of the window responded?” Global average pooling (GAP) does this over the whole map and leaves one number per channel, making the representation independent of where the object appeared.

Symbols

\(A^k\): feature map of channel \(k\), shape \(H\times W\) · \(C\): channel count · \(N\): batch size · \(K_{pool}\): pooling window · \(S\): pooling stride · \(o\): output-channel index.

The math

1 · Max and average pooling

Pooling uses the same output-size formula as convolution with dilation 1:

\[ H' = \left\lfloor \frac{H + 2P - K_{pool} - 1}{S} \right\rfloor + 1 \] \[ \mathrm{max}_A(i,j) = \max_{0\le u,v Worked example on this 4×4 map, with \(K_{pool}=2, S=2, P=0\):

\[ A=\begin{bmatrix}1&5&2&8\\3&4&7&6\\9&2&1&5\\0&3&8&4\end{bmatrix} \]

Output size: \(\lfloor(4-2-1)/2\rfloor+1=2\), so 2×2. The four maxima are \(\max\{1,5,3,4\}=5\), \(\max\{2,8,7,6\}=8\), \(\max\{9,2,0,3\}=9\), \(\max\{1,5,8,4\}=8\):

\[ \mathrm{max}_A = \begin{bmatrix}5&8\\9&8\end{bmatrix}, \qquad \mathrm{avg}_A = \begin{bmatrix}3.25&5.75\\3.5&4.5\end{bmatrix} \]

(For the first average: \((1+5+3+4)/4=13/4=3.25\). Pooling has no learnable parameters and keeps the channel count unchanged.)

2 · Global average pooling

\[ \mathrm{GAP}: (N,C,H,W) \rightarrow (N,C), \qquad \bar A_{n,o} = \frac{1}{HW}\sum_{i=1}^{H}\sum_{j=1}^{W} A_{n,o,i,j} \]

Worked example: \(N=1, C=2, H=W=2\), with channel 1 \(\begin{bmatrix}1&3\\5&7\end{bmatrix}\) and channel 2 \(\begin{bmatrix}2&4\\6&8\end{bmatrix}\). Means: \((1+3+5+7)/4=4\) and \((2+4+6+8)/4=5\). The output is the vector \((4,5)\), shape \((1,2)\). A linear head then maps 2 numbers to class logits instead of flattening \(C\cdot H\cdot W\) numbers.

3 · Why pooling gives (approximate) invariance

If a bright pixel moves from column \(j\) to \(j+1\) inside the same 2×2 window, the max over that window is unchanged. So a max-pooled feature is invariant to shifts up to the window width — but only locally, and only while the feature stays in the same window. Crossing a window boundary changes the output. That is why the invariance is approximate, and why pooling too early can destroy information needed for localisation.

Hands-on labs

Every number below is computed in your browser from the inputs you can change.

Code

import torch
from torch import nn

model = nn.Sequential(
    nn.Conv2d(3, 16, 3, padding=1), nn.ReLU(),   # (N,16,H,W)
    nn.MaxPool2d(2),                             # (N,16,H/2,W/2)
    nn.Conv2d(16, 32, 3, padding=1), nn.ReLU(),  # (N,32,H/2,W/2)
)

activation = {}
def grab(name):
    def hook(module, inp, out):
        activation[name] = out.detach()          # (N, C, H', W')
    return hook
model[3].register_forward_hook(grab("conv2"))    # index 3 = second Conv2d

x = torch.randn(2, 3, 32, 32)                    # (N, C, H, W)
y = model(x)                                     # (2, 32, 16, 16)
print(activation["conv2"].shape)                 # (2, 32, 16, 16)

gap = nn.AdaptiveAvgPool2d(1)
z = gap(activation["conv2"])                     # (2, 32, 1, 1)
z = torch.flatten(z, 1)                          # (2, 32)
logits = nn.Linear(32, 10)(z)                    # (2, 10)
print(z.shape, logits.shape)

Common mistakes

Filter vs feature map

The filter is the fixed K×K×C_in weight tensor; the feature map is the H′×W′ output it produces at one location and channel. Calling both “kernel” hides what a hook records.

Pooling too early

A 2×2 pool at the start throws away half the positions before later layers can use them. Tasks that need localisation (detection, segmentation) often replace pooling with stride or keep higher-resolution skips.

GAP for localisation

GAP averages away position. It is excellent for whole-image classification with weak labels, wrong for predicting where an object is.

Assuming pooling learns

Max/average pooling contain no parameters. Only conv (and learned downsampling such as stride-2 conv) changes its behaviour through training.

Debug this

A reader replaces torch.flatten(x, 1) after global average pooling with the GAP output itself. The Linear layer then reports a shape mismatch: its input is (2,32,1,1) but it expects (2,32).

Show the likely cause and the fix

AdaptiveAvgPool2d(1) returns shape \((N,C,1,1)\), not \((N,C)\). Flatten the two singleton spatial dimensions before the linear layer: z = torch.flatten(gap(x), 1). Then nn.Linear(C, n_classes) receives \((N,C)\). The lab shows the same GAP step as a vector of channel means.

In Keras, GlobalAveragePooling2D() already returns \((N,C)\) — do not flatten again there.

Summary

1 · A filter is the shared weight tensor; a feature map is the H′×W′ response of that filter at one output channel.
2 · Max/average pooling use the output-size formula with no parameters: the lesson's 4×4 example gives [[5,8],[9,8]] and [[3.25,5.75],[3.5,4.5]].
3 · GAP maps (N,C,H,W) to (N,C); pooling trades location for approximate invariance, so localisation tasks keep higher-resolution maps.

Cheat sheet — M1·03

  • Pool output: \(H'=\lfloor(H+2P-K_{pool}-1)/S\rfloor+1\).
  • Max pool: \(\max_{u,v}A_{iS+u,jS+v}\); average pool divides the window sum by \(K_{pool}^2\).
  • Worked 4×4 pool: rows (1,5,2,8)/(3,4,7,6)/(9,2,1,5)/(0,3,8,4) give max [[5,8],[9,8]].
  • GAP: \((N,C,H,W)\to(N,C)\), one mean per channel.
  • Pooling parameters: 0. Channel count is unchanged.
  • Forward hook stores the conv output; flatten GAP's (N,C,1,1) before Linear.
