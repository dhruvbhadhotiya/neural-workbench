Autoencoders: learn the bottleneck

— · Lesson 1 of 5 · Exact math labs

An autoencoder is a compressor you train instead of derive. Shrink the middle, and the network must discover which features of the data are worth keeping — we will watch that happen live.

Objectives

  • Train a 2→k→2 autoencoder on a curved 2-D cloud and read its reconstruction error.
  • Explain the bottleneck with a rank argument, and show why a linear autoencoder is just PCA.
  • Compute sparse, contractive and denoising objectives with concrete numbers.
  • Choose when an autoencoder helps and when its reconstruction loss is misleading.

You know this from ML → here it becomes

PCA compresses by computing one eigenvector problem on your data matrix. An autoencoder compresses by learning an encoder \(\mathbf h = f(\mathbf x)\) and a decoder \(\hat{\mathbf x} = g(\mathbf h)\) with gradient descent. With linear \(f,g\) and squared error, the two give the same subspace. With a nonlinearity, the autoencoder can bend that subspace into a curve — which is the whole reason to learn it.

Intuition: a narrow middle forces discovery

Let \(\mathbf x \in \mathbb{R}^{D}\) be one input, \(\mathbf h \in \mathbb{R}^{k}\) its latent code, and \(\hat{\mathbf x}\) the reconstruction. The encoder uses parameters \(\theta_e\), the decoder \(\theta_d\); together \(\theta = \{\theta_e,\theta_d\}\). If \(k < D\), the code is a bottleneck: a \(k\)-dimensional vector cannot carry all \(D\) coordinates, so the network must keep structure and discard noise. If \(k \ge D\), an identity map fits perfectly and teaches you nothing.

The interesting case is data that only looks \(D\)-dimensional. A curved line in the plane needs two coordinates to write down, but only one number to locate a point along it. An autoencoder with \(k=1\) can unroll that curve; PCA can only draw its best straight line through it. That difference — curve versus line — is what the first lab makes visible.

A bottleneck is a compression budget. Too small and the reconstruction blurs; too large and the network memorises the identity. The useful middle is where reconstruction stays good and the code is smaller than the input.

The math

1 · Reconstruction loss

With \(N\) samples and squared error summed over the \(D\) coordinates, the mean squared error (MSE) is

\[ \mathcal{L}_{\text{rec}}(\theta) = \frac{1}{N}\sum_{n=1}^{N}\lVert \hat{\mathbf x}_n - \mathbf x_n\rVert_2^2, \qquad \hat{\mathbf x}_n = g_\theta(f_\theta(\mathbf x_n)) \]

Worked example. One 2-D point \(\mathbf x = (2,-1)\) is reconstructed as \(\hat{\mathbf x} = (1.6,-0.8)\). The errors are \(2-1.6 = 0.4\) and \(-1+0.8 = -0.2\); squared, \(0.16 + 0.04 = 0.20\). With \(D=2\), the per-coordinate MSE is \(0.20/2 = 0.10\). All losses below use this mean over samples and coordinates reduction unless stated.

2 · The bottleneck rank argument

If both encoder and decoder are linear maps \(\mathbf h = W_e\mathbf x\), \(\hat{\mathbf x}=W_d\mathbf h\), then \(\hat{\mathbf x} = (W_dW_e)\mathbf x\). The product of a \(D\times k\) and a \(k\times D\) matrix has rank at most \(k\). So the reconstruction lives in at most a \(k\)-dimensional subspace of \(\mathbb{R}^D\), even if the data does not.

Worked example. With \(D=3, k=1\), take the \(1\times 3\) encoder \(W_e=(1,1,0)\) and the \(3\times 1\) decoder \(W_d=(1,1,0)^\top\). For \(\mathbf x=(2,3,4)\), the code is \(h=2+3+0=5\), and \(\hat{\mathbf x}=W_dh=(5,5,0)\): only one direction survives, so the third coordinate is lost completely. A nonlinear encoder escapes this rank bound because \(h\) can be any scalar function of \(\mathbf x\).

3 · Linear autoencoder = PCA

Let the centred data covariance be \(C = \frac{1}{N}\sum_n(\mathbf x_n-\boldsymbol\mu)(\mathbf x_n-\boldsymbol\mu)^\top\), with eigenvectors \(\mathbf v_1,\ldots,\mathbf v_D\) ordered by eigenvalue \(\lambda_1\ge\lambda_2\ge\cdots\). The optimal rank-\(k\) linear encoder projects onto the top \(k\) eigenvectors: \(h_i = (\mathbf x-\boldsymbol\mu)^\top\mathbf v_i\), and the decoder reverses it, \(\hat{\mathbf x}=\boldsymbol\mu+\sum_{i=1}^{k}h_i\mathbf v_i\). The minimal MSE is \(\frac{1}{D}\sum_{i=k+1}^{D}\lambda_i\) — the variance you threw away.

Worked example. Take four centred points \((1,2),(2,1),(-1,-2),(-2,-1)\). Their covariance is \(C=\begin{bmatrix}2.5&2\\2&2.5\end{bmatrix}\), with \(\mathbf v_1=(1,1)/\sqrt 2\), \(\lambda_1=4.5\) and \(\mathbf v_2=(1,-1)/\sqrt 2\), \(\lambda_2=0.5\). For \(k=1\) and \(\mathbf x=(2,1)\): \(h_1=(2+1)/\sqrt 2 = 2.1213\), so \(\hat{\mathbf x}=2.1213(1,1)/\sqrt 2=(1.5,1.5)\). Squared error \(= (0.5)^2+(-0.5)^2 = 0.5\), matching \(\lambda_2=0.5\); reduced over \(D=2\) coordinates, the MSE is \(0.5/2=0.25\). The retained variance fraction is \(4.5/(4.5+0.5)=0.90\).

4 · Sparse penalty

To force a sparse code, add an \(\ell_1\) penalty on the hidden activation: \(\mathcal{L} = \mathcal{L}_{\text{rec}} + \lambda\lVert \mathbf h\rVert_1 = \mathcal{L}_{\text{rec}} + \lambda\sum_{j=1}^{k}|h_j|\), where \(\lambda > 0\) is the penalty strength. Unlike \(\ell_2\), \(\ell_1\) pushes small activations exactly to zero.

Worked example. For \(\mathbf h=(0.5,-0.2,0)\) and \(\lambda=0.1\): \(\lVert\mathbf h\rVert_1 = 0.5+0.2+0 = 0.7\), penalty \(=0.1\times 0.7 = 0.07\). If the reconstruction term was \(0.10\), the total objective is \(0.17\).

5 · Contractive penalty

A contractive autoencoder discourages sensitivity of the code to small input changes. With the Jacobian \(J = \partial\mathbf h/\partial\mathbf x \in \mathbb{R}^{k\times D}\), the penalty is \(\lambda\lVert J\rVert_F^2 = \lambda\sum_{i,j}J_{ij}^2\), where \(\lVert\cdot\rVert_F\) is the Frobenius norm (square root of the sum of squared entries).

Worked example. Suppose \(k=D=2\) and \(J=\begin{bmatrix}1&0\\0.5&0\end{bmatrix}\). Then \(\lVert J\rVert_F^2 = 1^2+0^2+0.5^2+0^2 = 1.25\). With \(\lambda=0.01\) the penalty is \(0.0125\); added to the \(0.10\) reconstruction MSE from above, the objective is \(0.1125\).

6 · Denoising autoencoder

Corrupt the input to \(\tilde{\mathbf x} = \mathbf x + \boldsymbol\varepsilon\), with \(\varepsilon_j\sim\mathcal N(0,\sigma^2)\), and train the network to reconstruct the clean \(\mathbf x\): \(g(f(\tilde{\mathbf x}))\approx\mathbf x\). For a linear rank-1 autoencoder with top eigenvalue \(\lambda_1\) and discarded eigenvalue \(\lambda_2\), the exact expected MSE is \(\lambda_2+\sigma^2\). With optimal shrinkage of the noisy code by \(\lambda_1/(\lambda_1+\sigma^2)\), it is \(\lambda_2+\lambda_1\sigma^2/(\lambda_1+\sigma^2)\).

Worked example. Let \(\lambda_1=2.5,\lambda_2=0.5,\sigma=1\). Plain projection gives \(0.5+1^2 = 1.5\). Shrinkage gives \(0.5 + 2.5\cdot 1/(2.5+1) = 0.5+0.7143 = 1.2143\). The second lab computes both curves from a real covariance matrix, not from a hand-drawn sketch.

Code

A synthetic curved point cloud, a 2→k→2 autoencoder, and a latent plot. The only training trick worth noting is that the target equals the input: this is self-supervised, no labels are needed. Shapes are written in NCHW-free 2-D form here because the data is a point cloud, not an image batch. 

import torch
from torch import nn

torch.manual_seed(0)

# Synthetic curved 2-D manifold: shape (512, 2)
t = torch.empty(512).uniform_(-1.25, 1.25)
x = torch.stack([t + 0.04 * torch.randn(512),
                 0.55 * t**3 - 0.35 * t + 0.05 * torch.randn(512)], dim=1)
k = 1

class Autoencoder(nn.Module):
    def __init__(self, k):
        super().__init__()
        self.enc = nn.Sequential(nn.Linear(2, k), nn.Tanh())   # (N, 2) -> (N, k)
        self.dec = nn.Sequential(nn.Linear(k, 8), nn.Tanh(),
                                 nn.Linear(8, 2))              # (N, k) -> (N, 2)

    def forward(self, x):
        h = self.enc(x)          # latent code, shape (N, k)
        return self.dec(h), h

model = Autoencoder(k)
opt = torch.optim.Adam(model.parameters(), lr=0.01)   # lr = η

for step in range(2000):
    xhat, h = model(x)                         # self-supervised target is x itself
    loss = ((xhat - x) ** 2).mean()            # MSE, mean over N and D
    opt.zero_grad()
    loss.backward()
    opt.step()

with torch.no_grad():
    xhat, h = model(x)
    mse = ((xhat - x) ** 2).mean().item()
    print("MSE", round(mse, 4), "latent", tuple(h.shape))  # (512, 1)
import numpy as np

# The linear special case: top-k eigenvectors of the centred covariance.
Xc = x.detach().numpy() - x.detach().numpy().mean(axis=0)   # (512, 2), centred
C = Xc.T @ Xc / len(Xc)                                     # (2, 2) covariance
w, V = np.linalg.eigh(C)                                    # ascending eigenvalues
v1 = V[:, -1]                                               # top eigenvector, shape (2,)

h = Xc @ v1                       # encode: (512, 2) @ (2,) -> (512, 1)
Xhat = np.outer(h, v1) + x.detach().numpy().mean(axis=0)
print("top eigenvalue", round(w[-1], 3),
      "MSE", round(np.mean((Xhat - x.detach().numpy()) ** 2), 3))

The PCA check is not a different model — it is the closed-form solution a linear autoencoder converges to. The PyTorch version with nn.Tanh() can do better because it is not restricted to a straight subspace.

Common mistakes

Bottleneck too small

With \(k=1\) on intrinsically 2-D data, MSE rises sharply and reconstructions blur into a line. That is not a training bug — it is the compression budget. Compare against a non-degenerate baseline before increasing \(k\).

Bottleneck too large

With \(k \ge D\), the identity map reaches zero loss while learning nothing about structure. A beautiful reconstruction at \(k=D\) is not evidence of useful features.

No normalisation

MSE is in squared input units, so a feature measured in thousands dominates a feature in units. Standardise features first; otherwise the autoencoder spends its capacity on the largest scale rather than the most informative direction.

Judging by loss alone

A low reconstruction loss does not imply good downstream features, and an autoencoder is not a generator — sampling random \(\mathbf h\) from nowhere usually gives nonsense. Use a downstream task for features and a VAE or GAN for generation.

Debug this

A reader reports: “my latent size is 1, yet reconstruction is pixel-perfect from the first step.” The training loop is fine. The model definition is not: 

class BrokenAE(nn.Module):
    def forward(self, x):
        h = self.enc(x)                 # shape (N, 1)
        return x + self.dec(h), h       # BUG: input is added to the output
Show the likely cause and the fix

The + x is a skip connection. The decoder only has to learn zero, and the reconstruction is the input regardless of the bottleneck. Remove it: return self.dec(h), h. A more subtle version of the same bug stores the uncorrupted input in a global and returns it during denoising training.

Quick detector: set the latent to a constant vector by hand. If the output still equals the input, information is bypassing the bottleneck.

Check yourself

Summary

1 · An autoencoder learns \(\mathbf h=f(\mathbf x)\) and \(\hat{\mathbf x}=g(\mathbf h)\) by minimising \(\frac{1}{ND}\sum\lVert\hat{\mathbf x}-\mathbf x\rVert^2\); the bottleneck limits the rank of a linear version to \(k\).
2 · Linear + MSE is PCA: the optimal code is the projection on \(\mathbf v_1,\ldots,\mathbf v_k\), with error \(\frac{1}{D}\sum_{i>k}\lambda_i\).
3 · Sparse, contractive and denoising terms change what the code preserves; low reconstruction loss alone is not proof of useful features.

Cheat sheet — M4·01

  • \(\mathcal{L}_{\text{rec}} = \frac{1}{ND}\sum_{n,i}(\hat x_{n,i}-x_{n,i})^2\). Worked: (2,−1)→(1.6,−0.8) gives 0.10.
  • Rank bound: \(\mathrm{rank}(W_dW_e)\le k\). Linear AE = PCA; error \(=\frac{1}{D}\sum_{i>k}\lambda_i\).
  • Sparse: \(\mathcal{L}+\lambda\lVert\mathbf h\rVert_1\). Worked: \(\mathbf h=(0.5,-0.2,0),\lambda=0.1\Rightarrow 0.07\).
  • Contractive: \(\lambda\lVert\partial\mathbf h/\partial\mathbf x\rVert_F^2\). Worked: \(J=[[1,0],[0.5,0]],\lambda=0.01\Rightarrow 0.0125\).
  • Denoising: train \(g(f(\mathbf x+\varepsilon))\approx\mathbf x\); for rank 1, MSE \(=\lambda_2+\sigma^2\).
  • Check a suspicious AE by replacing \(\mathbf h\) with a constant: the output must change.
