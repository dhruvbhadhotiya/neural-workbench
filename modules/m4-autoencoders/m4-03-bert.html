BERT: contextual vectors from masked language modelling

— · Lesson 3 of 5 · Illustrative lab

Word2Vec gives one fixed vector per word. BERT gives one vector per token in context — and it learns that context by hiding words and asking the model to recover them.

Objectives

  • Explain masked language modelling (MLM) and next-sentence prediction (NSP) from their losses.
  • Read WordPiece tokens, special tokens and an attention mask in a fixed input sequence.
  • Compute an MLM softmax over a 5-token vocabulary and the cross-entropy at the true token.
  • Attach a classification head to \([\text{CLS}]\) and fine-tune with a small learning rate.

You know this from ML → here it becomes

A bag-of-words classifier ignores order; a Word2Vec embedding gives the same vector for “bank” in every sentence. BERT stacks bidirectional transformer encoder blocks, so the vector for a token is a function of its whole input sequence. Pretraining is self-supervised (no human labels), and a small task-specific head turns those contextual vectors into predictions.

Intuition: hide a word, predict a word

A BERT input is a sequence of tokens. \([\text{CLS}]\) starts it, \([\text{SEP}]\) separates segments, and WordPiece splits rare words into subwords marked with ##. Each input token is the sum of a token embedding, a segment embedding (which sentence it belongs to) and a positional embedding. The transformer encoder applies self-attention, so every output vector can see every input token — unlike the causal model we will meet in Lesson 4.

During pretraining, about 15% of tokens are replaced by \([\text{MASK}]\) and the model must predict the original token at those positions. Because prediction uses both left and right context, this is a masked language model, not an autoregressive one. The second pretraining task, NSP, asks whether sentence B followed sentence A in the original text; it uses the \([\text{CLS}]\) vector as a binary classifier input.

BERT does not predict the next word. It fills blanks using both directions, and the vector it produces for a token changes when the surrounding sentence changes — that is what “contextual” means.

The math

1 · MLM loss and a 5-token softmax

Let \(M\) be the set of masked positions and \(V\) the vocabulary. For a masked position \(i\), the encoder produces logits \(\mathbf z_i\in\mathbb R^{|V|}\); the probability of token \(w\) is \(\mathrm{softmax}(\mathbf z_i)_w\). The loss averages cross-entropy over the masked positions:

\[ \mathcal L_{\text{MLM}}=-\frac{1}{|M|}\sum_{i\in M}\log\,\mathrm{softmax}(\mathbf z_i)_{w_i}, \qquad \mathrm{softmax}(\mathbf z)_j=\frac{e^{z_j}}{\sum_{k\in V}e^{z_k}} \]

Here \(w_i\) is the true (hidden) token at position \(i\), and \(|V|\) is the vocabulary size. The reduction is a mean over masked positions, not over every token in the sequence.

Worked example over a 5-token toy vocabulary. Let the logits at one masked position be \(\mathbf z=(2,1,0,-1,-2)\) for tokens (cat, mat, dog, floor, sofa). The exponentials are \((7.389,2.718,1.000,0.368,0.135)\), summing to \(11.610\). The probabilities are \((0.6366,0.2341,0.0861,0.0317,0.0116)\). If the hidden token was “mat” (index 1), the loss at this position is \(-\log 0.2341=1.452\) nats. If it was “cat”, the loss is only \(-\log 0.6366=0.452\) nats. Temperature is 1 here; no scaling is applied.

2 · Attention block recap

Each encoder block uses scaled dot-product attention with query \(Q\), key \(K\), value \(V\) matrices and key dimension \(d_k\):

\[ \mathrm{Attention}(Q,K,V)=\mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V \]

\(Q,K,V\in\mathbb R^{T\times d_k}\) for \(T\) tokens; dividing by \(\sqrt{d_k}\) keeps the dot products from growing with dimension and saturating the softmax.

Worked example. Take \(d_k=4\), one query with scores \(QK^\top=(4,0)\) against two keys, and value rows \(\mathbf v_1=(1,0)\), \(\mathbf v_2=(0,1)\). Scaling gives \((4/2,0/2)=(2,0)\); \(\mathrm{softmax}(2,0)=(0.8808,0.1192)\). The output is \(0.8808(1,0)+0.1192(0,1)=(0.8808,0.1192)\) — mostly the first value. A \([\text{PAD}]\) position is excluded by setting its attention logit to \(-\infty\), which gives it weight zero.

3 · Next-sentence prediction

NSP pools the \([\text{CLS}]\) output \(\mathbf h_{\text{CLS}}\in\mathbb R^D\) through a linear layer and a sigmoid: \(p=\sigma(\mathbf w^\top\mathbf h_{\text{CLS}}+b)\in(0,1)\), with target \(y\in\{0,1\}\). The loss is binary cross-entropy \(\mathcal L_{\text{NSP}}=-[y\log p+(1-y)\log(1-p)]\).

Worked example. Let \(\mathbf w^\top\mathbf h_{\text{CLS}}+b=1.5\), so \(p=1/(1+e^{-1.5})=0.8176\). If the true label is “not next” (\(y=0\)), the loss is \(-\log(1-0.8176)=-\log(0.1824)=1.702\) nats. If the label is “next” (\(y=1\)), the loss is \(-\log 0.8176=0.201\) nats. NSP was later criticised because the task is easy to solve with topic cues rather than true coherence; many later models dropped it.

4 · A fine-tuning head

For a \(C\)-class task, attach \(W\in\mathbb R^{C\times D}\) to the pooled vector and train cross-entropy: \(\mathcal L=-\log\,\mathrm{softmax}(W\mathbf h_{\text{CLS}}+\mathbf b)_y\). The pretrained encoder is usually fine-tuned with a learning rate around \(10^{-5}\) to a few times \(10^{-5}\), far below the \(10^{-3}\) used for a randomly initialised head.

Worked example. With 3-class logits \((0.5,2.0,-1.0)\), exponentials are \((1.649,7.389,0.368)\), summing to \(9.406\). Probabilities are \((0.175,0.786,0.039)\). For target class 1 the loss is \(-\log 0.786=0.241\) nats. A larger learning rate can destroy the pretrained representations before the head converges.

Code

The first listing is the Hugging Face fine-tuning skeleton for a PyTorch model: the tokenizer builds \((N,T)\) token ids and an attention mask, and the head is attached by AutoModelForSequenceClassification. Nothing is downloaded at build time — run this in your own Colab. The second listing computes the MLM softmax by hand so you can check the arithmetic above. Shapes use \((N,T)\), where \(N\) is batch size and \(T\) sequence length. 

from transformers import AutoTokenizer, AutoModelForSequenceClassification
from transformers import TrainingArguments, Trainer
import torch

CHECKPOINT = "bert-base-uncased"       # choose a checkpoint before running
tokenizer = AutoTokenizer.from_pretrained(CHECKPOINT)

sentences = ["The cat sat on the mat.", "The dog slept on the sofa."]
labels = [0, 1]                        # already remapped to 0..C-1

batch = tokenizer(sentences, padding=True, truncation=True,
                  max_length=128, return_tensors="pt")
# batch["input_ids"]      shape (N=2, T)
# batch["attention_mask"] shape (N=2, T); 1 = real token, 0 = padding

model = AutoModelForSequenceClassification.from_pretrained(
    CHECKPOINT, num_labels=2)          # adds a head on top of [CLS]

args = TrainingArguments(
    output_dir="./out", learning_rate=2e-5,   # small LR for fine-tuning
    num_train_epochs=3, per_device_train_batch_size=8,
)
trainer = Trainer(model=model, args=args,
                  train_dataset=None)   # supply a torch Dataset of encoded rows
# trainer.train()                       # uncomment in Colab

with torch.no_grad():
    logits = model(**batch).logits      # shape (N, C=2), pre-softmax
print("logits", tuple(logits.shape))
import torch
import torch.nn.functional as F

# One masked position, five-token toy vocabulary (synthetic numbers).
logits = torch.tensor([2.0, 1.0, 0.0, -1.0, -2.0])   # shape (V=5,)
target = torch.tensor(1)                              # the hidden token "mat"

p = F.softmax(logits, dim=-1)          # (5,) ~ (0.6366, 0.2341, 0.0861, ...)
loss = F.cross_entropy(logits.unsqueeze(0), target.unsqueeze(0))
print("probs", [round(v, 4) for v in p.tolist()])
print("loss", round(loss.item(), 4))   # -log(0.2341) ~ 1.452

# Scaled dot-product attention on T=4 tokens, key dim d_k=4.
Q = torch.randn(2, 4, 8, 4)            # (N, heads=2, T=4, d_k=4)
K = torch.randn(2, 4, 8, 4)
V = torch.randn(2, 4, 8, 4)
scores = Q @ K.transpose(-1, -2) / (4 ** 0.5)   # (2, 8, 4, 4)
attn = torch.softmax(scores, dim=-1) @ V        # (2, 8, 4, 4)
print("attention output", tuple(attn.shape))

The \([\text{CLS}]\) vector is a convenience for classification, not magic: some models pool over all tokens instead. Check the checkpoint's documentation before assuming which vector a head should consume, and always pass the tokenizer's attention_mask so padded positions cannot contribute.

Common mistakes

Using [CLS] for every model

Not every encoder uses \([\text{CLS}]\), and some checkpoints pool the final hidden states differently. Read the model card: attaching a head to the wrong vector still trains, but it throws away the representation the checkpoint was built to expose.

Forgetting the attention mask

A padded token is still a real row of ids unless you pass attention_mask. Without it, attention attends to padding and the pooled vector shifts with batch length — especially damaging when you pad on the right in one batch and the left in another.

Wrong tokenizer for the checkpoint

A cased checkpoint needs a cased tokenizer, and WordPiece vocabularies are not interchangeable. A mismatch silently changes token ids and ## continuations, so the model sees a different sequence from the one it was pretrained on.

Fine-tuning at 1e-3

That learning rate is typical for a head trained from scratch, but often far too large for pretrained weights: it can erase useful representations in a few steps. Start in the 1e-5 range for the encoder and use a larger rate only for the new head if needed.

Debug this

A reader reports: “binary accuracy is exactly 50% on a two-class task and never moves.” The model and optimiser look fine. The labels do not: 

raw = df["label"].tolist()              # values are -1 and +1
dataset = [tokenizer(s, truncation=True) | {"labels": y}
           for s, y in zip(df["text"], raw)]
# BUG: the head has 2 output classes, but labels are -1 and +1
Show the likely cause and the fix

Cross-entropy with class indices expects labels in \(\{0,\ldots,C-1\}\). With labels \(-1\) and \(+1\), index \(-1\) wraps to the last class and index \(+1\) selects the second: the mapping is inconsistent with how the head was created, so the model cannot learn a useful decision. Remap explicitly: labels = [(y + 1) // 2 for y in raw] for \(-1/+1\), or use a label dictionary in general. Verify with set(labels) == {0, 1} before training.

Quick detector: print the unique label values and the head's num_labels in the same line. A 50% plateau on a balanced two-class problem is a classic sign that the target encoding, not the model, is broken.

Summary

1 · BERT pretrains a bidirectional transformer encoder with MLM, recovering masked tokens from both directions; with toy logits \((2,1,0,-1,-2)\) the second token's probability is \(2.718/11.610=0.2341\).
2 · Attention computes \(\mathrm{softmax}(QK^\top/\sqrt{d_k})V\); segment ids, positional ids and an attention mask define which tokens can contribute.
3 · Fine-tuning attaches a small head to a pooled vector and uses a learning rate near \(10^{-5}\), with labels remapped to \(0,\ldots,C-1\).

Cheat sheet — M4·03

  • \(\mathcal L_{\text{MLM}}=-\frac{1}{|M|}\sum_{i\in M}\log\mathrm{softmax}(z_i)_{w_i}\). Worked: (2,1,0,−1,−2) → p(mat)=0.2341, loss 1.452.
  • \(\mathrm{Attention}(Q,K,V)=\mathrm{softmax}(QK^\top/\sqrt{d_k})V\). Worked: scores (4,0), d_k=4 → weights (0.881, 0.119).
  • NSP: \(p=\sigma(w^\top h_{\text{CLS}}+b)\); worked logit 1.5 → p=0.818, loss 1.702 for y=0.
  • Head: \(-\log\mathrm{softmax}(Wh_{\text{CLS}}+b)_y\); logits (0.5,2,−1) → loss 0.241 for class 1.
  • WordPiece \(##\) = subword continuation; attention mask 0 marks padding; special tokens [CLS], [SEP], [MASK].
  • Fine-tune the encoder near 1e-5 and check that labels are 0..C−1 before training.
