Losses, computation graphs and backpropagation

— · Lesson 2 of 5 · Exact math labs

Backpropagation is the chain rule with bookkeeping. Work one tiny network all the way through, then watch the browser check every gradient you derived.

Objectives

  • Derive the backward pass of a 2→3→1 network using local derivatives.
  • Write MSE, BCE and cross-entropy with their derivatives and reductions.
  • Explain what autograd caches and why .grad accumulates.
  • Verify an analytic gradient against a central-difference approximation.

You know this from ML → here it becomes

In logistic regression you differentiated the log-loss once and got \(\nabla_W\mathcal{L} = (p-y)x\). Nothing new is needed for a deep net: each layer contributes its own local derivative, and the chain rule multiplies them from the output back to the input. The only new habit is caching the forward values that the backward pass needs.

Intuition: blame flows backwards

A forward pass is a relay race. Each layer receives an activation, computes a weighted sum, applies a nonlinearity and hands the result to the next layer. Training is a second race run in reverse: the loss hands each layer a number that says “how much did you move the error?” That number is the gradient with respect to the layer's output. Multiply by the layer's local derivative, pass the result further back, and repeat.

The reason this is efficient is reuse. A naive differentiation of the whole network would recompute the same subexpressions for every parameter. Backprop stores one gradient per intermediate value and reuses it for all parameters upstream, so one forward pass plus one backward pass gives every gradient at once.

Forward: compute and remember. Backward: multiply the incoming gradient by each local derivative, going from the loss to the parameters. Same cost order for any depth.

The math

Symbols used in this lesson

\(\mathbf{x}\in\mathbb{R}^{2}\) one input; \(\mathbf{W}_1\in\mathbb{R}^{3\times2}\), \(\mathbf{b}_1\in\mathbb{R}^{3}\) first-layer parameters; \(\mathbf{z}_1\) pre-activation; \(\mathbf{h}=\phi(\mathbf{z}_1)\) hidden activation with \(\phi=\mathrm{ReLU}\); \(\mathbf{W}_2\in\mathbb{R}^{1\times3}\), \(b_2\) output parameters; \(\hat y = z_2\) the scalar prediction; \(y\) the target; \(N\) batch size; \(\mathcal{L}\) the scalar loss; \(\delta_l=\partial\mathcal{L}/\partial\mathbf{z}_l\) the error signal at layer \(l\); \(\eta\) the learning rate; \(\theta\) all parameters. We use the mean reduction over \(N\) unless stated otherwise.

1 · The chain rule, one local step at a time

If \(a=\phi(z)\) and \(\mathcal{L}\) depends on \(a\), then

\[ \frac{\partial\mathcal{L}}{\partial z} = \frac{\partial\mathcal{L}}{\partial a}\,\frac{\partial a}{\partial z} = \frac{\partial\mathcal{L}}{\partial a}\,\phi'(z) \]

Worked numbers with the mean-squared-error loss for one sample. Take \(\mathbf{x}=(1,2)\), \(\mathbf{W}_1=\begin{bmatrix}0.5&-0.4&0.2\\0.1&0.3&-0.2\end{bmatrix}\), \(\mathbf{b}_1=(0.1,-0.1,0.05)\), \(\mathbf{W}_2=(1.0,\,-0.5,\,2.0)\) and \(b_2=0.2\), target \(y=0.5\).

Forward: \(\mathbf{z}_1 = (0.5+0.2+0.1,\;-0.4+0.6-0.1,\;0.2-0.4+0.05) = (0.80,\,0.10,\,-0.15)\), so \(\mathbf{h}=(0.80,\,0.10,\,0)\) after ReLU. Then \(z_2 = 0.80(1.0)+0.10(-0.5)+0(2.0)+0.2 = 0.95\) and \(\mathcal{L}=(0.95-0.5)^2 = 0.2025\).

Backward: \(\partial\mathcal{L}/\partial z_2 = 2(\hat y-y) = 2(0.95-0.5) = 0.9\). ReLU derivatives at \(z_1\) are \((1,1,0)\), so the error signal reaching the first layer is \(\boldsymbol\delta_1 = \mathbf{W}_2^\top(0.9)\odot(1,1,0) = (0.9,\,-0.45,\,1.8)\odot(1,1,0) = (0.9,\,-0.45,\,0)\). The third hidden unit is dead: its gradient is exactly zero.

2 · The Jacobian view

For a vector layer, the local derivative is a Jacobian \(J\) with \(J_{ij}=\partial a_i/\partial z_j\). An elementwise activation has a diagonal Jacobian:

\[ J_\phi = \operatorname{diag}\big(\phi'(z_1),\dots,\phi'(z_D)\big) \]

With \(\mathbf{z}_1=(0.80,0.10,-0.15)\) above, \(J_\phi=\operatorname{diag}(1,1,0)\). A gradient vector \((0.9,-0.45,1.8)\) entering this layer leaves as \((0.9,-0.45,0)\). Frameworks never build the full diagonal matrix; they store the three numbers and multiply elementwise.

3 · Losses and their derivatives

MSE for regression, with \(\hat y_n\) the prediction and \(y_n\) the target:

\[ \mathcal{L}_{\text{MSE}}=\frac{1}{N}\sum_{n=1}^{N}\lVert \hat y_n-y_n\rVert^2, \qquad \frac{\partial\mathcal{L}}{\partial\hat y_n}=\frac{2}{N}(\hat y_n-y_n) \]

Worked with \(\hat y=(0.95,2.05)\), \(y=(0.5,1.0)\), \(N=2\): errors \((0.45,1.05)\), squares \((0.2025,1.1025)\), mean \(\mathcal{L}=0.6525\). The gradient is \((2\cdot0.45/2,\,2\cdot1.05/2)=(0.45,1.05)\).

BCE for probabilities \(\hat y\in(0,1)\) and binary targets \(y\in\{0,1\}\):

\[ \mathcal{L}_{\text{BCE}}=-\frac{1}{N}\sum_{n=1}^{N} \big[y_n\log\hat y_n+(1-y_n)\log(1-\hat y_n)\big], \qquad \frac{\partial\mathcal{L}}{\partial\hat y_n} =-\frac{1}{N}\left(\frac{y_n}{\hat y_n}-\frac{1-y_n}{1-\hat y_n}\right) \]

Worked with \(\hat y=(0.8,0.2)\), \(y=(1,0)\), \(N=2\): the two per-sample losses are \(-\log 0.8=0.2231\) and \(-\log(1-0.2)=0.2231\), so \(\mathcal{L}=0.2231\). Gradients: \(-1/(2\cdot0.8)=-0.625\) and \(+1/(2\cdot0.8)=+0.625\). If you have logits \(z\) instead, use the fused BCE-with-logits form \(\max(z,0)-zy+\log(1+e^{-|z|})\); it avoids \(\log 0\).

Cross-entropy for \(K\) classes, logits \(\mathbf{z}\), target index \(y\):

\[ \mathrm{softmax}(\mathbf{z})_i=\frac{e^{z_i}}{\sum_j e^{z_j}},\qquad \mathcal{L}_{\text{CE}}=-\log\mathrm{softmax}(\mathbf{z})_y,\qquad \frac{\partial\mathcal{L}}{\partial\mathbf{z}}=\mathrm{softmax}(\mathbf{z})-\mathbf{e}_y \]

Worked with \(\mathbf{z}=(2.0,1.0,0.1)\) and \(y=1\): \(e^{2.0}=7.3891,\;e^{1.0}=2.7183,\;e^{0.1}=1.1052\), sum \(=11.2126\). Probabilities \((0.6592,0.2424,0.0986)\), so \(\mathcal{L}=-\log 0.2424=1.4171\). The gradient is \((0.6592,\;0.2424-1,\;0.0986)=(0.6592,-0.7576,0.0986)\). The elegant cancellation is why frameworks fuse softmax and CE.

Hinge for targets \(y\in\{-1,+1\}\):

\[ \mathcal{L}_{\text{hinge}}=\frac{1}{N}\sum_n\max(0,1-y_n\hat y_n),\qquad \frac{\partial\mathcal{L}}{\partial\hat y_n}=\begin{cases}-y_n/N & y_n\hat y_n<1\\0&\text{otherwise}\end{cases} \]

Worked with \(\hat y=0.4\), \(y=+1\), \(N=1\): \(1-1(0.4)=0.6>0\), so \(\mathcal{L}=0.6\) and the gradient is \(-1\). A confident correct point \(\hat y=1.4\) gives loss \(0\) and gradient \(0\).

4 · The full backward recurrence

For layer \(l\) with activation \(\phi_l\), incoming error \(\boldsymbol\delta_{l+1}\), weight matrix \(\mathbf{W}_{l+1}\) and cached input activation \(\mathbf{a}_{l-1}\):

\[ \boldsymbol\delta_l = (\mathbf{W}_{l+1}^\top\boldsymbol\delta_{l+1})\odot\phi_l'(\mathbf{z}_l), \qquad \frac{\partial\mathcal{L}}{\partial\mathbf{W}_l}=\boldsymbol\delta_l\,\mathbf{a}_{l-1}^\top, \qquad \frac{\partial\mathcal{L}}{\partial\mathbf{b}_l}=\boldsymbol\delta_l \]

Continue the worked network from §1. With \(\delta_2=0.9\), the output weights get \(\partial\mathcal{L}/\partial\mathbf{W}_2=(h_1\delta_2)= (0.8\cdot0.9,\,0.1\cdot0.9,\,0\cdot0.9)=(0.72,0.09,0)\), while \(\partial\mathcal{L}/\partial b_2=\delta_2=0.9\). The first-layer gradients are \(\boldsymbol\delta_1(1,2)=(0.9,1.8)\), \((0,-0.45,0)\), \((0,0,0)\) in the three columns: explicitly \(\partial\mathcal{L}/\partial\mathbf{W}_1= \begin{bmatrix}0.9&-0.45&0\\1.8&-0.9&0\end{bmatrix}\) and \(\partial\mathcal{L}/\partial\mathbf{b}_1=(0.9,-0.45,0)\). A gradient-descent step with \(\eta=0.1\) would change \(W_{1,1,1}\) from \(0.1\) to \(0.08\): \(0.1-0.1(1.8)=0.08\).

5 · What autograd actually stores

When you call loss.backward(), a framework walks the graph built during the forward pass and applies each operation's local derivative. It needs the forward values: multiplying by \(\mathbf{W}\) needs the input, and multiplying by \(\mathbf{x}\) needs \(\mathbf{W}\). That is why memory grows with batch size even at inference-like model size, and why torch.no_grad() saves memory at evaluation.

  • Leaf tensors are parameters you created with requires_grad=True; they receive a .grad buffer.
  • Intermediate tensors hold the graph edges and cached values; their gradients are freed after use unless retained.
  • Accumulation means .grad is added to, not overwritten — deliberate for gradient accumulation, disastrous if forgotten in a normal loop.
  • Numerical check: central difference \(\frac{f(\theta+\varepsilon)-f(\theta-\varepsilon)}{2\varepsilon}\) with \(\varepsilon=10^{-5}\) should match the analytic gradient to a relative error near \(10^{-6}\).

Worked check for one scalar parameter: if \(f(\theta)=\theta^2\), at \(\theta=3\), analytic \(\nabla=6\); with \(\varepsilon=10^{-5}\), \((3.00001^2-2.99999^2)/(2\cdot10^{-5}) = (9.0000600001-8.9999400001)/0.00002 = 6\).

Code

The hand derivation in PyTorch. Note that .grad is populated on the leaf tensors only, and that gradcheck needs double precision and freshly created leaves. 

import torch

# Same network as the worked example: 2 -> 3 (ReLU) -> 1, mean squared error.
torch.manual_seed(0)
x = torch.tensor([1., 2.], dtype=torch.float64)  # shape (2,), match parameter dtype
y = torch.tensor(0.5, dtype=torch.float64)       # scalar target
W1 = torch.tensor([[0.5, -0.4, 0.2],             # shape (2, 3)
                   [0.1,  0.3, -0.2]], dtype=torch.float64, requires_grad=True)
b1 = torch.tensor([0.1, -0.1, 0.05], dtype=torch.float64, requires_grad=True)
W2 = torch.tensor([[1.0], [-0.5], [2.0]], dtype=torch.float64, requires_grad=True)  # (3, 1)
b2 = torch.tensor([0.2], dtype=torch.float64, requires_grad=True)

z1 = x @ W1 + b1                                 # (3,) : [0.8, 0.1, -0.15]
h = torch.relu(z1)                               # (3,) : [0.8, 0.1, 0.0]
z2 = h @ W2 + b2                                 # (1,) : [0.95]
loss = (z2 - y).pow(2).mean()                    # scalar : 0.2025
loss.backward()                                  # fills .grad on W1, b1, W2, b2

print("z1", [round(v, 4) for v in z1.tolist()])
print("loss", round(loss.item(), 4))
print("dW1", W1.grad.tolist())                   # [[0.9,-0.45,0],[1.8,-0.9,0]]
print("db1", b1.grad.tolist())                   # [0.9,-0.45,0]
print("dW2", W2.grad.tolist())                   # [[0.72],[0.09],[0.0]]
print("db2", b2.grad.tolist())                   # [0.9]

# Numerical check: rebuild fresh leaves (gradcheck perturbs them) and use float64.
p = [t.detach().clone().requires_grad_(True) for t in (W1, b1, W2, b2)]
def f(a, c, d, e):
    return ((torch.relu(x @ a + c) @ d + e - y) ** 2).sum()
print("gradcheck", torch.autograd.gradcheck(f, p))  # True

# In a training loop, ALWAYS clear the accumulated gradients first:
# optimizer.zero_grad(); loss.backward(); optimizer.step()

Common mistakes

Gradients accumulate silently

PyTorch adds to .grad. Without zero_grad() the second step uses roughly twice the true gradient, the third three times, and the loss eventually explodes. Accumulate on purpose only when simulating a larger batch.

In-place edits on graph tensors

Modifying a tensor needed for backward (for example x.add_(1) after it was used) corrupts the saved value and raises a version-counter error. Build a new tensor instead; leave in-place updates to optimizer step on leaf parameters.

Softmax applied twice

CELoss expects probabilities while CrossEntropyLoss expects logits. Passing logits to the former gives nonsense; applying your own softmax before the latter flattens the gradient. Choose one fused operation.

Sign or reduction mistakes

Descent subtracts the gradient; ascent adds it. Check the reduction too: a sum over a batch of 64 is 64× larger than a mean, which effectively multiplies \(\eta\) by 64.

Debug this

A reader trains a 4-layer classifier. The loss falls for ~20 steps, then rises, then becomes nan. The learning rate is reasonable, the data is normalized, and the labels look correct. The training loop is:

Show the likely cause and the fix

The loop is missing optimizer.zero_grad(). Gradients from earlier minibatches are still in every .grad buffer, so the effective learning rate grows with the step count. Add it before loss.backward() and the loss will be smooth again.

Diagnostic: print p.grad.abs().max() for one parameter on the first three steps. If it grows roughly 1×, 2×, 3× with identical-looking batches, accumulation is the cause. If it is already huge on step 1, inspect the loss reduction or the learning rate.

Summary

1 · Backprop is the chain rule applied locally: δₗ = (Wₗ₊₁ᵀδₗ₊₁) ⊙ φ′(zₗ), and ∂L/∂Wₗ = δₗaₗ₋₁ᵀ.
2 · Fused CE gives the clean gradient softmax(z) − e_y; MSE and BCE need the 2/N or 1/N reduction kept straight.
3 · Autograd caches forward values and accumulates gradients — clear them each step and verify with finite differences.

Cheat sheet — M0·02

  • Chain rule: \(\partial\mathcal{L}/\partial z = (\partial\mathcal{L}/\partial a)\,\phi'(z)\).
  • ReLU′(z) = 1 for z > 0, 0 for z < 0; zero-gradient units are “dead”.
  • MSE: \(\frac{1}{N}\sum(\hat y-y)^2\), gradient \(2(\hat y-y)/N\).
  • BCE: \(-y\log\hat y-(1-y)\log(1-\hat y)\); use logits + fused loss.
  • CE: \(-\log\mathrm{softmax}(z)_y\), gradient \(\mathrm{softmax}(z)-e_y\).
  • Order: zero_grad() → backward() → step().
  • Gradient check: \((f(\theta+\varepsilon)-f(\theta-\varepsilon))/(2\varepsilon)\), \(\varepsilon=10^{-5}\).
