The PyTorch workflow, end to end

— · Lesson 5 of 5 · Exact math labs

fit() is a convenience, not magic. Own the loop once and every later debugging problem becomes a matter of inspecting one line at a time.

Objectives

  • Write a complete training loop with a Dataset and DataLoader.
  • Trace tensor shapes and count parameters through linear and convolutional stacks.
  • Evaluate with model.eval() and torch.no_grad().
  • Save and restore a checkpoint containing model and optimizer state.

You know this from ML → here it becomes

clf.fit(X, y) bundles batching, shuffling, optimization and evaluation into one call. Here you write those five stages yourself. The payoff is that a shape mismatch, a device mismatch or a stale optimizer state has exactly one place to look.

Intuition: the seven lines that matter

Every framework loop contains the same ingredients: build tensors, wrap them in a dataset, shuffle batches, move them to the device, compute a loss, differentiate, update. Evaluation repeats the forward pass with gradients disabled and the model in eval mode. A checkpoint stores enough state to resume later: parameters, optimizer buffers, epoch and metrics.

Most runtime errors are shape errors in disguise. A linear layer expects its last dimension to equal its fan-in; a conv expects NCHW; cross-entropy expects logits of shape \((N,K)\) and labels of shape \((N)\). Trace these on paper before adding complexity.

Write the loop once, print one batch of shapes, and keep a checkpoint with both model and optimizer state. Everything later — CNNs, RNNs, GANs — uses the same skeleton.

The math: a worked shape trace

Symbols and conventions

\(N\) batch size; \(C\) channels; \(H,W\) spatial size; \(D\) feature width; \(K\) kernel size; \(S\) stride; \(P\) zero padding; \(d\) dilation; \(\mathbf{X}\) a batch of inputs; \(\mathbf{W}\) a weight matrix; \(\mathbf{b}\) a bias; \(\hat y\) prediction; \(y\) label; \(\mathcal{L}\) loss; \(\theta\) all parameters. Images are always written in NCHW order.

1 · Dense network (N = 64, 784 → 128 → 10)

\[ \mathbf{Z}_1 = X\mathbf{W}_1+\mathbf{b}_1,\quad \mathbf{A}_1=\mathrm{ReLU}(\mathbf{Z}_1),\quad \hat y=\mathrm{softmax}(A_1\mathbf{W}_2+\mathbf{b}_2) \]

Shapes: \(X\in\mathbb{R}^{64\times784}\), \(\mathbf{W}_1\in\mathbb{R}^{784\times128}\), \(\mathbf{b}_1\in\mathbb{R}^{128}\), so \(\mathbf{Z}_1\) and \(\mathbf{A}_1\) are \((64,128)\). \(\mathbf{W}_2\in\mathbb{R}^{128\times10}\), \(\mathbf{b}_2\in\mathbb{R}^{10}\), so the logits are \((64,10)\), the softmax is \((64,10)\), and cross-entropy with labels \(y\in\{0,\dots,9\}^{64}\) returns one scalar.

Parameters: layer 1 has \(784\cdot128+128=100{,}352+128=100{,}480\); layer 2 has \(128\cdot10+10=1{,}290\). Total \(\theta\): \(100{,}480+1{,}290=101{,}770\).

2 · Convolutional stack and the one output-size formula

\[ H' = \left\lfloor \frac{H + 2P - d(K-1) - 1}{S} \right\rfloor + 1 \]

Start with \(\mathsf{X}\in\mathbb{R}^{2\times3\times32\times32}\) (N=2, C=3, H=W=32). A conv with \(C_{out}=16\), \(K=3\), \(P=1\), \(S=1\), \(d=1\) gives \(H'=\lfloor(32+2\cdot1-1(3-1)-1)/1\rfloor+1=\lfloor31\rfloor+1=32\), so the output is \((2,16,32,32)\). Its parameters are \(K^2 C C_{out}+C_{out}=9\cdot3\cdot16+16=432+16=448\).

A max-pool with \(K=2,S=2,P=0\) gives \(H'=\lfloor(32+0-1(2-1)-1)/2\rfloor+1=\lfloor30/2\rfloor+1=16\), output \((2,16,16,16)\). Flattening produces \(16\cdot16\cdot16=4096\) features per sample, shape \((2,4096)\). A final linear layer \(4096\to10\) has \(4096\cdot10+10=40{,}970\) parameters. Total \(448+40{,}970=41{,}418\).

Lab: trace shapes through your own stack

Add layers, change the input shape, and watch every output shape and parameter count update. The convolution and pooling rows show the substituted arithmetic for the output-size formula; a linear layer applied to a feature map deliberately reports a shape error until you insert Flatten.

Code

Two complete training loops on the same synthetic binary task. The PyTorch version uses TensorDataset, DataLoader and a checkpoint; the Keras version uses a tf.data pipeline and a manual GradientTape loop rather than fit(). Keras image layers default to NHWC internally; these examples use dense inputs, so no image-layout conversion is needed here. 

import torch
from torch import nn
from torch.utils.data import TensorDataset, DataLoader

torch.manual_seed(0)
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")

# Synthetic classification data: (512, 4) features, 2 classes.
X = torch.randn(512, 4)
y = (X[:, 0] + X[:, 1] > 0).long()
loader = DataLoader(TensorDataset(X, y), batch_size=32, shuffle=True)

model = nn.Sequential(nn.Linear(4, 16), nn.ReLU(), nn.Linear(16, 2)).to(device)
opt = torch.optim.Adam(model.parameters(), lr=1e-2)
loss_fn = nn.CrossEntropyLoss()                    # logits (N, 2), labels (N,)

for epoch in range(1, 11):
    model.train()
    total = 0.0
    for xb, yb in loader:                          # shapes (32, 4) and (32,)
        xb, yb = xb.to(device), yb.to(device)      # device must match the model
        opt.zero_grad()
        logits = model(xb)
        loss = loss_fn(logits, yb)
        loss.backward()
        opt.step()
        total += loss.item() * len(yb)
    model.eval()
    with torch.no_grad():                          # no graph, no parameter updates
        pred = model(X.to(device)).argmax(dim=1)   # dim=1 selects the class axis
        acc = (pred == y.to(device)).float().mean().item()
    print(f"epoch {epoch:2d}  train loss {total/len(X):.4f}  acc {acc:.3f}")

torch.save({
    "model": model.state_dict(),
    "optimizer": opt.state_dict(),
    "epoch": 10,
}, "checkpoint.pt")

# Restore into a fresh model / optimizer before resuming training.
model2 = nn.Sequential(nn.Linear(4, 16), nn.ReLU(), nn.Linear(16, 2)).to(device)
opt2 = torch.optim.Adam(model2.parameters(), lr=1e-2)
ckpt = torch.load("checkpoint.pt", map_location=device, weights_only=False)
model2.load_state_dict(ckpt["model"])
opt2.load_state_dict(ckpt["optimizer"])
print("restored epoch", ckpt["epoch"])
import tensorflow as tf

tf.random.set_seed(0)
X = tf.random.normal([512, 4])
y = tf.cast(X[:, 0] + X[:, 1] > 0, tf.int32)
ds = tf.data.Dataset.from_tensor_slices((X, y)).shuffle(512).batch(32)

model = tf.keras.Sequential([
    tf.keras.layers.Dense(16, activation="relu", input_shape=(4,)),
    tf.keras.layers.Dense(2),                      # logits, shape (N, 2)
])
opt = tf.keras.optimizers.Adam(1e-2)
loss_fn = tf.keras.losses.SparseCategoricalCrossentropy(from_logits=True)

@tf.function
def train_step(xb, yb):
    with tf.GradientTape() as tape:                # records operations for backprop
        logits = model(xb, training=True)
        loss = loss_fn(yb, logits)
    grads = tape.gradient(loss, model.trainable_variables)
    opt.apply_gradients(zip(grads, model.trainable_variables))
    return loss

for epoch in range(1, 11):
    total, count = 0.0, 0
    for xb, yb in ds:
        loss = train_step(xb, yb)
        total += float(loss) * len(yb); count += len(yb)
    logits = model(X, training=False)              # eval mode: no dropout / BN updates
    acc = tf.reduce_mean(tf.cast(tf.argmax(logits, axis=1) == y, tf.float32))
    print(f"epoch {epoch:2d}  train loss {total/count:.4f}  acc {float(acc):.3f}")

model.save_weights("checkpoint.weights.h5")
model2 = tf.keras.Sequential([
    tf.keras.layers.Dense(16, activation="relu", input_shape=(4,)),
    tf.keras.layers.Dense(2),
])
model2.build([None, 4])
model2.load_weights("checkpoint.weights.h5")       # restore parameters
print("restored", len(model2.trainable_variables), "variable tensors")

Both loops print values computed at runtime — no two runs with different seeds match digit for digit. The API surface differs, but the seven stages (data, batch, device, forward, loss, backward, step) are identical.

Common mistakes

Forgetting no_grad()

Evaluation still builds a graph and stores activations. It gives correct numbers but wastes memory; wrap the eval forward pass in torch.no_grad().

.item() vs tensor

.item() extracts a Python number and detaches it from the graph. Useful for logging, wrong if you intend to differentiate through the value. Accumulate losses with loss.item() * batch_size to avoid keeping the graph alive.

Wrong argmax axis

Logits have shape \((N,K)\), so classes live on axis 1. Using dim=0 compares different samples and yields meaningless predictions.

Device and dtype mismatch

A CPU tensor added to a CUDA parameter raises an error. Move inputs, labels and any manually created buffers to the same device as the model; keep floating data in float32 (or float16 with mixed precision).

Debug this

A reader adds a convolution before their classifier and gets a mat1 and mat2 shapes cannot be multiplied error mentioning 32×8192 and 1024×10. The model definition is otherwise unchanged.

Show the likely cause and the fix

The feature map was never flattened. After the conv and pool blocks the tensor has shape \((N,C,H,W)\); nn.Linear wants a matrix whose last axis matches its fan-in. Insert nn.Flatten() before the first linear layer, or call x = x.reshape(x.size(0), -1) in forward().

To find the expected fan-in, print one batch: print(x.shape) just before the failing layer. Here \(C\cdot H\cdot W = 8192\), not 1024 — the linear layer was built for an older, smaller input.

Summary

1 · The training loop is data → batch/device → forward → loss → backward → step, with eval in no_grad() mode.
2 · Trace shapes before running: dense layers need (N,D), convs need NCHW, and a 4096-feature flatten feeds a 40,970-parameter linear layer.
3 · Save model state, optimizer state and the step counter together so a run can be resumed exactly.

Cheat sheet — M0·05

  • Linear params: \(D_{in}D_{out}+D_{out}\); conv params: \(K^2 C_{in}C_{out}+C_{out}\).
  • Output size: \(H'=\lfloor(H+2P-d(K-1)-1)/S\rfloor+1\).
  • 784→128→10: 101,770 parameters. 3→16 conv k3 on 32×32: 448 parameters.
  • Logits shape \((N,K)\), labels \((N)\), class axis 1.
  • Loop: zero_grad → forward → loss → backward → step.
  • Eval: model.eval() + torch.no_grad(); train again with model.train().
  • Checkpoint: model state + optimizer state + epoch + metrics.
